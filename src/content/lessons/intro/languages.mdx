## Три оси, по которым языки отличаются

Синтаксис — это поверхность: скобки, отступы, точки с запятой. За неделю привыкаешь к любому. Языки по-настоящему отличаются тремя решениями, и именно о них спрашивают на собесах.

### 1. Кто управляет памятью

| Подход | Языки | Цена |
|---|---|---|
| **Вручную** — `malloc`/`free` | C, C++ (частично) | быстро и предсказуемо, но утечки, use-after-free, дыры в безопасности |
| **Сборщик мусора** | Java, Go, Python, JS, C# | безопасно и удобно, но паузы GC и больше памяти |
| **Владение, проверка при компиляции** | Rust, C++ (RAII) | безопасно и быстро, но компилятор строже и учиться дольше |

Это главный водораздел. «Почему Java, а не C++ для бэкенда» — это вопрос про память. «Почему Discord переписал сервис с Go на Rust» — тоже: паузы GC.

### 2. Когда проверяются типы

- **Статическая типизация** (Java, C, Go, Rust, TypeScript): ошибку `"5" + число` ловит компилятор до запуска. Большие кодовые базы держатся на этом.
- **Динамическая** (Python, JS, Ruby): тип проверяется в момент выполнения. Писать быстрее, но ошибки всплывают в проде.

Индустрия пришла к середине: в Python появились type hints и mypy, в JS — TypeScript. То есть динамические языки догоняют статику аннотациями.

### 3. Как исполняется

- **Компиляция в машинный код** заранее (C, C++, Go, Rust) — быстрый старт и скорость, но под каждую платформу своя сборка.
- **Байткод + виртуальная машина + JIT** (Java, C#, JS в V8) — один бинарник везде, JIT разгоняет горячий код по ходу работы.
- **Интерпретация** (CPython) — самый медленный путь, но самый гибкий: пишешь — сразу запускаешь.

<Callout kind="tip" title="На собесе">
«Почему Python медленный?» Хороший ответ: интерпретатор байткода без JIT; все значения — объекты в куче со счётчиком ссылок; GIL не даёт потокам выполнять байткод параллельно. Поэтому быстрые части — numpy, pandas, PyTorch — написаны на C и C++, а Python их только склеивает.
</Callout>

## Парадигмы — это ответы на сложность

Ещё одна ось — **как организовать мысль**, когда программа большая.

- **Процедурная** (C, Fortran): программа — последовательность шагов и функций. Хорошо, пока программа помещается в голову.
- **Объектно-ориентированная** (Smalltalk → C++ → Java): данные и поведение вместе, объект отвечает за свои правила. Ответ на «гигантские C-программы, где любая функция портит любую структуру». Об этом — трек «ООП».
- **Функциональная** (Lisp → Haskell → лямбды везде): чистые функции без побочных эффектов, данные не меняются. Ответ на «состояние меняется где попало, и баги невозможно воспроизвести», особенно в многопоточности. Трек «Функциональное программирование».
- **Декларативная** (SQL, HTML, Kubernetes YAML): описываешь результат, а не шаги. Как достичь — решает движок.

Современные языки смешивают всё: в Java есть классы, лямбды и стримы, в Python — классы, генераторы и `functools`. Поэтому учить стоит идеи, а не «Java-способ» или «Python-способ».

## Как выбирают язык в реальности

Почти никогда не по красоте. На деле решают четыре вещи:

1. **Экосистема.** ML — Python, потому что там PyTorch. Android — Kotlin. Браузер — JS/TS: альтернатив нет.
2. **Люди.** Банк на Java, потому что Java-разработчиков легко нанять, а код живёт 20 лет.
3. **Требования к ресурсам.** Микроконтроллер на 64 КБ — C. Высокочастотный трейдинг — C++. Сервис с SLA на паузы — Go или Rust вместо JVM.
4. **Уже написанный код.** Переписывать дорого. Поэтому живы COBOL в банках и Fortran в науке.

| Где | Чаще всего | Почему |
|---|---|---|
| Бэкенд в банках и корпорациях | Java, Kotlin, C# | экосистема, найм, долгоживущий код |
| Стартапы и API | Python, TypeScript, Go | скорость разработки |
| Инфраструктура и облака | Go, Rust | один бинарник, мало памяти, конкурентность |
| ML и данные | Python (+ C++/CUDA внутри) | экосистема |
| Фронтенд | TypeScript | браузер понимает только JS |
| Встраиваемые системы | C, C++, немного Rust | нет ОС, мало памяти, нужна предсказуемость |
| Игры | C++, C# (Unity) | скорость, движки |

<Takeaways>
- Процессор понимает только машинный код; любой язык — переводчик. **Каждый язык чинил конкретную боль** — найди её, и поймёшь язык.
- Главные различия не в синтаксисе, а в трёх решениях: **кто управляет памятью** (вручную, GC, владение), **когда проверяются типы** (статика или динамика), **как исполняется** (машинный код, байткод+JIT, интерпретатор).
- Парадигмы — ответы на сложность: процедуры → объекты → чистые функции → декларативность. Современные языки смешивают их все.
- Язык выбирают по экосистеме, людям, ресурсам и существующему коду, а не по красоте.
</Takeaways>
