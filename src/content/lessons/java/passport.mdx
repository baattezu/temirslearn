Прежде чем учить синтаксис, полезно понять характер языка: кто его сделал, против какой боли, на что он ставит и чем за это платит. Тогда странности Java — многословность, `public static void main`, вечная обратная совместимость — перестают быть странностями и становятся решениями.

## Откуда взялась

1991 год, Sun Microsystems. Команда **Джеймса Гослинга** («Green Project») делает софт для бытовой электроники: приставок, пультов, телевизоров. Устройства разные, процессоры разные, и писать на C++ под каждый — боль. Ещё больнее — ошибки памяти: телевизор, который падает из-за висячего указателя, никто не перезагрузит отладчиком.

Рынок «умных телевизоров» тогда не взлетел. Зато в 1995 году взлетел веб, и оказалось, что язык, который запускается на любом железе и не даёт программе испортить чужую память, — ровно то, что нужно, чтобы загружать код из интернета в браузер. Так появилась **Java 1.0** (1995) со слоганом **«Write once, run anywhere»**. Апплеты в браузере давно умерли, а язык переехал на серверы — и остался там на 30 лет.

## На что Java ставит

У каждого языка есть ставки. У Java они такие:

1. **Переносимость через виртуальную машину.** Компилируешь не в машинный код, а в байткод для JVM. Один `.jar` работает на Linux, Windows и macOS.
2. **Безопасность памяти.** Нет указателей и ручного `free`: сборщик мусора, проверка границ массивов, `NullPointerException` вместо порчи памяти.
3. **Простота важнее выразительности.** Изначально — «C++ без опасного»: без перегрузки операторов, множественного наследования классов и макросов. Код получается многословным, но его одинаково читают тысячи людей в большой команде.
4. **Обратная совместимость почти любой ценой.** Код 2004 года компилируется и сегодня. Поэтому банки и спокойно сидят на Java, и поэтому некоторые старые решения (стирание типов в дженериках, `Date`) остались навсегда.

<Callout kind="info" title="Как понимать «многословность»">
`public static void main(String[] args)` — не прихоть. `public` — виден JVM, `static` — вызывается без объекта, `void` — ничего не возвращает, `String[] args` — аргументы командной строки. Всё явно, ничего не подразумевается. С Java 21–25 для обучения можно писать просто `void main()` — язык тоже меняется.
</Callout>

## Как исполняется код

Самое важное, что стоит понимать про Java, — это путь от исходника до процессора:

`.java` → **javac** → `.class` (байткод) → **JVM**: загрузчик классов → интерпретатор → **JIT**-компилятор → машинный код.

Байткод — это команды **стековой машины**: операции берут аргументы с вершины стека и кладут результат обратно. Ниже — настоящий байткод, который `javac` выдаёт для маленького метода. Пройди его по шагам и посмотри, как `s += x * x` превращается в `iload`, `imul`, `iadd`.

<BytecodeStepper />

Двадцать с лишним инструкций на три элемента массива — интерпретировать так миллиарды операций было бы медленно. Поэтому JVM **следит, какой код горячий**, и компилирует его в машинный код прямо во время работы — по реальному профилю: какие ветки срабатывают, какие типы приходят.

<JitTiers />

Отсюда два практических следствия:
- **Java-сервис «прогревается».** Первые минуты после старта он медленнее, пока JIT не скомпилировал горячие пути. Поэтому при деплое трафик подают постепенно.
- **Микробенчмарк через `System.nanoTime()` врёт** — он меряет то интерпретатор, то C2, то вообще выкинутый как мёртвый код цикл. Для замеров есть JMH.

## Платформа больше, чем язык

JVM пережила моду на сам язык Java: на ней работают **Kotlin** (основной язык Android и всё чаще бэкенда), **Scala** (Spark, Kafka изначально), **Clojure** и **Groovy** (Gradle). Все они компилируются в тот же байткод, используют те же библиотеки, тот же GC и JIT.

Экосистема — главная сила Java:
- **Spring** — де-факто стандарт корпоративного бэкенда;
- драйверы и клиенты ко всему на свете;
- лучшие в индустрии инструменты наблюдения: JFR, async-profiler, heap dumps;
- **Kafka, Elasticsearch, Cassandra, Hadoop, Spark** — написаны на JVM-языках.

## Где Java живёт, а где её нет

| Живёт | Почему |
|---|---|
| бэкенд банков, финтеха, телекома, госсектора | надёжность, экосистема, долгая поддержка, легко нанять |
| высоконагруженные сервисы | зрелые GC и JIT, хорошая конкурентность |
| большие данные (Kafka, Spark, Flink) | исторически написаны на JVM |
| Android (через Kotlin) | платформа Google |

| Не живёт | Почему |
|---|---|
| фронтенд | браузер понимает только JS/WASM |
| микроконтроллеры | JVM и GC не влезают в килобайты; нужна предсказуемость |
| короткие CLI-утилиты, serverless с холодным стартом | старт JVM и прогрев — сотни миллисекунд (лечится GraalVM native-image, но с ограничениями) |
| ML-исследования | экосистема на Python |
| игры | паузы GC и нет доступа к железу — исключение Minecraft |

<Callout kind="tip" title="На собесе">
«Почему Java, а не Go/Python для этого сервиса?» Сильный ответ — про компромиссы, а не про вкус: экосистема и найм, зрелые инструменты диагностики, производительность после прогрева против времени старта и потребления памяти.
</Callout>

## JDK, JRE, OpenJDK — что есть что

- **JVM** — виртуальная машина, исполняет байткод.
- **JRE** — JVM + стандартная библиотека: чтобы запускать.
- **JDK** — JRE + компилятор и инструменты (`javac`, `jcmd`, `jfr`): чтобы разрабатывать.
- **OpenJDK** — открытая эталонная реализация. Сборки от разных вендоров (Temurin, Corretto, Zulu, Oracle) — по сути одно и то же. Oracle JDK в проде может требовать коммерческой лицензии — поэтому обычно берут Temurin или Corretto.

<Takeaways>
- Java (1995, Гослинг, Sun) — ответ на две боли C++: **разное железо** и **ошибки памяти**. Отсюда JVM и сборщик мусора.
- Ставки: переносимость, безопасность памяти, простота для больших команд, **обратная совместимость**.
- Путь кода: `javac` → **байткод стековой машины** → интерпретатор → **JIT** (C1, C2) по профилю. Отсюда прогрев и неверные «наивные» бенчмарки.
- Эпохи: Java 5 (дженерики) → 8 (лямбды) → 17 (record, sealed) → 21 (виртуальные потоки) → 25.
- **JVM — платформа**: Kotlin, Scala, Kafka, Spark. Живёт в бэкенде и данных; нет её во фронтенде, микроконтроллерах и ML-исследованиях.
</Takeaways>
