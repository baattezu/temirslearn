## Типы: примитивы и ссылки

Главное отличие от Python: у переменной **статический тип**, и типы бывают двух сортов.

- **Примитивы** — `int`, `long`, `double`, `boolean`, `char`, `byte`, `short`, `float`. Лежат прямо в переменной, без объекта. `int` — 32 бита и переполняется молча: `Integer.MAX_VALUE + 1 == Integer.MIN_VALUE`.
- **Ссылки** — всё остальное: `String`, массивы, любые объекты. Переменная хранит адрес объекта в куче; может быть `null`.

```java
int a = 5;            // примитив, значение
Integer b = 5;        // объект-обёртка (autoboxing)
var list = new ArrayList<String>();   // var: тип выводится, но он статический
long big = 3_000_000_000L;            // L — литерал long
double price = 0.1 + 0.2;             // 0.30000000000000004 — для денег BigDecimal
```

<Callout kind="warn" title="Ловушка №1: == для объектов">
`==` сравнивает **ссылки**. Строки и обёртки сравнивай через `equals`: `"abc".equals(s)`. `Integer` от −128 до 127 кэшируется, поэтому `==` «иногда работает» — это худший вид бага.
</Callout>

## Строки

`String` **неизменяемая**. Каждое `s + x` в цикле создаёт новую строку — для склейки в цикле есть `StringBuilder`.

```java
String s = "Java";
s.length();                // 4 — метод, не свойство
s.charAt(0);               // 'J' — char в одинарных кавычках
s.substring(1, 3);         // "av"
String.format("%s = %d", "x", 42);
"""
    Текстовый блок —
    многострочная строка (Java 15+)
    """;
var sb = new StringBuilder();
for (int i = 0; i < 3; i++) sb.append(i).append(',');
```

## Коллекции

Массивы фиксированной длины — редко. В коде почти всегда **интерфейс** слева, реализация справа:

```java
List<String> names = new ArrayList<>();   // динамический массив
names.add("Ада");
Map<String, Integer> age = new HashMap<>();
age.put("Ада", 36);
age.getOrDefault("Алан", 0);
Set<Integer> seen = new HashSet<>();

List<Integer> fixed = List.of(1, 2, 3);   // неизменяемый: add() бросит исключение
for (var e : age.entrySet()) System.out.println(e.getKey() + " " + e.getValue());
```

Дженерики (`List<String>`) проверяются компилятором, но в рантайме **стираются**: внутри это просто `List` объектов. Поэтому нельзя `new T()` и `List<int>` — только `List<Integer>`.

```java
interface Shape { double area(); }                 // контракт
record Circle(double r) implements Shape {
    public double area() { return Math.PI * r * r; }
}
sealed interface Result permits Ok, Err {}        // закрытый набор вариантов (17+)
record Ok(String value) implements Result {}
record Err(String message) implements Result {}

String show(Result r) {
    return switch (r) {                            // pattern matching (21+)
        case Ok(var v) -> "ok: " + v;
        case Err(var m) -> "ошибка: " + m;         // компилятор проверит, что все варианты разобраны
    };
}
```

Модификаторы доступа: `private` (только класс), без модификатора (пакет), `protected` (пакет + наследники), `public` (все). Правило — **всё private, пока не нужно иначе**.

## Исключения

В Java два вида исключений, и это частый вопрос на собесе:

- **checked** (`IOException`, `SQLException`) — компилятор **заставляет** обработать или объявить `throws`. Идея — нельзя забыть про ожидаемые сбои.
- **unchecked** (`RuntimeException` и наследники: `NullPointerException`, `IllegalArgumentException`) — ошибки программиста, объявлять не нужно.

```java
try (var reader = Files.newBufferedReader(path)) {   // try-with-resources: reader закроется сам
    return reader.readLine();
} catch (NoSuchFileException e) {
    return null;
} catch (IOException e) {
    throw new UncheckedIOException(e);                 // заворачиваем, сохраняя причину
}
```

На практике checked-исключения многие считают неудачным экспериментом: в лямбдах и стримах с ними неудобно, поэтому Spring и современные библиотеки бросают unchecked.

## null и Optional

`NullPointerException` — самая частая ошибка в Java. Защиты:

```java
Optional<User> u = repo.findById(id);       // «может не быть» явно в типе
String name = u.map(User::name).orElse("гость");
Objects.requireNonNull(arg, "arg");         // fail fast на входе
```

`Optional` — для **возвращаемых значений**, а не для полей и параметров.

## Чего в Java нет, к чему привыкнуть

- Нет функций вне классов — есть `static`-методы.
- Нет перегрузки операторов: `BigDecimal` складывают через `a.add(b)`.
- Нет значений параметров по умолчанию — перегрузка методов или Builder.
- Нет множественного наследования классов — только интерфейсов (с `default`-методами).
- Нет беззнаковых чисел (кроме `char`).

<Takeaways>
- Всё внутри классов; **статическая типизация**; блоки — `{}`, строки кончаются `;`.
- **Примитивы** (`int`, `long`, `double`…) против **ссылок** (всё остальное, может быть `null`). Объекты сравнивай через `equals`, не `==`.
- `String` неизменяема; склейка в цикле — `StringBuilder`.
- Коллекции: `List`/`Map`/`Set` слева, `ArrayList`/`HashMap`/`HashSet` справа; дженерики стираются.
- Современная Java: `var`, `record`, `sealed` + `switch` с pattern matching, текстовые блоки.
- Исключения **checked** (обязан обработать) и **unchecked**; try-with-resources закрывает ресурсы.
- Лямбды и **ленивые стримы**; `Optional` — для возвращаемых значений.
</Takeaways>
