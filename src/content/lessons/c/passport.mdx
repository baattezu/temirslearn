C старше почти всех, кто на нём пишет, и при этом остаётся в первой пятёрке языков. На нём написаны ядро Linux, интерпретатор Python, Postgres, SQLite, Redis, прошивки роутеров и микроволновок. Если представить софт как здание, C — это фундамент и несущие стены. Чтобы понять, почему он такой (опасный, минималистичный, быстрый), надо вернуться в Bell Labs.

## Откуда взялся

Конец 1960-х. **Кен Томпсон** и **Деннис Ритчи** пишут операционную систему Unix для мини-компьютера PDP-7 — на ассемблере. Потом переезжают на PDP-11, и становится понятно: каждая новая машина — это переписать всю ОС заново.

Томпсон сделал язык B (упрощённый BCPL), но в нём не было типов: всё было машинным словом. Ритчи добавил типы (`char`, `int`, структуры, указатели) — так в 1972 году появился **C**. В 1973 году ядро Unix переписали на C, и это перевернуло индустрию: ОС на языке высокого уровня можно **перенести на новое железо, просто написав компилятор**.

## Философия: доверяй программисту

Комитет по стандарту C сформулировал «дух C» прямо:

- **Доверяй программисту.**
- **Не мешай программисту делать то, что нужно.**
- **Язык маленький и простой.**
- **Одна операция — один способ.**
- **Сделай быстро, даже если это не гарантированно переносимо.**

C — это «переносимый ассемблер». Почти каждая конструкция языка ложится на несколько машинных инструкций, и ничего не происходит без твоего ведома: нет сборщика мусора, нет проверки границ массивов, нет исключений, нет скрытых аллокаций. Ты видишь, что стоит каждая строка.

Обратная сторона — **ответственность целиком на тебе**. Вышел за границу массива — испортил соседние данные, и программа упадёт через час в другом месте. Около 70% серьёзных уязвимостей в продуктах Microsoft и Chrome — ошибки безопасности памяти, и почти все они в коде на C и C++.

## Компилятор — твой соавтор

Код на C близок к железу, но не равен ему. Компилятор с оптимизациями переписывает программу очень агрессивно. Вот одна функция и что из неё сделал clang:

```c
long sum_to(long n) {
    long s = 0;
    for (long i = 1; i <= n; i++) s += i;
    return s;
}
```

## Что в C есть, а чего нет

| Есть | Нет |
|---|---|
| указатели и адресная арифметика | классов, методов, наследования |
| структуры, объединения, массивы | исключений — коды возврата и `errno` |
| ручная память: `malloc` / `free` | сборщика мусора |
| препроцессор: `#include`, `#define` | пространств имён — префиксы вроде `pg_`, `SDL_` |
| битовые операции, `volatile` для железа | дженериков — `void*` и макросы |
| компиляция в машинный код | проверки границ массивов |

Строка в C — это просто массив `char`, который кончается нулевым байтом `'\0'`. Длину каждый раз ищут проходом до нуля (`strlen`), а забытый ноль или лишний символ — классическое переполнение буфера.

## Почему C жив в 2025 году

1. **ABI и FFI.** C — «лингва франка» между языками: Python, Java (JNI, Panama), Rust, Go вызывают библиотеки через C-интерфейс. Любая библиотека, которую хотят использовать из всех языков, отдаёт C API.
2. **Везде есть компилятор.** Для любого микроконтроллера первым появляется компилятор C.
3. **Предсказуемость.** Нет пауз GC и скрытых аллокаций — для ядер, драйверов и реального времени это обязательно.
4. **Огромная кодовая база.** Linux — больше 30 миллионов строк, переписывать никто не будет. Но в ядро уже пускают Rust для новых драйверов.

## Где C живёт, а где его нет

| Живёт | Почему |
|---|---|
| ядра ОС, драйверы | контроль над памятью и железом, нет рантайма |
| встраиваемые системы, микроконтроллеры | килобайты памяти, предсказуемость |
| интерпретаторы и базы данных (CPython, Postgres, SQLite, Redis) | скорость и переносимость |
| библиотеки с API для всех языков | C ABI — общий знаменатель |

| Не живёт | Почему |
|---|---|
| бизнес-логика, веб-бэкенд | цена ошибки памяти и скорость разработки |
| новые проекты, где важна безопасность | Rust даёт ту же скорость с проверкой памяти компилятором |
| всё, где нужны строки, JSON, коллекции «из коробки» | в стандартной библиотеке их почти нет |

<Callout kind="tip" title="Зачем учить C, если на нём не писать">
Чтобы понимать, что происходит под твоим языком. Почему `ArrayList` быстрее `LinkedList`, откуда берутся `NullPointerException` и `segfault`, как устроен стек вызовов, что делает GC и что такое переполнение буфера — всё это проще всего увидеть в C.
</Callout>

<Takeaways>
- C (1972, Ритчи, Bell Labs) создан, чтобы писать **переносимую ОС**: Unix на C переносился на новое железо через компилятор.
- Дух C: **доверяй программисту**, язык маленький, всё видно, ничего скрытого. «Переносимый ассемблер».
- Цена — **безопасность памяти на тебе**: границы массивов, висячие указатели, UB. Большинство критичных уязвимостей — отсюда.
- Компилятор с оптимизациями переписывает код радикально — например, заменяет цикл формулой.
- C жив благодаря **C ABI** (общий интерфейс всех языков), компиляторам под любое железо, предсказуемости и огромной кодовой базе.
- Живёт в ядрах, драйверах, embedded, интерпретаторах и базах; не для бизнес-логики. Новые системные проекты всё чаще берут Rust.
</Takeaways>
