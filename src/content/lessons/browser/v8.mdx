JavaScript — динамический язык: у объекта в любой момент могут появиться новые поля, а функция может получить что угодно. Тем не менее V8 выполняет его со скоростью, близкой к Java. Секрет — в спекуляции: движок **предполагает**, что код ведёт себя предсказуемо, компилирует под это предположение и откатывается, если оно нарушилось.

## Конвейер V8

1. **Парсер** строит AST (лениво: тела функций разбираются при первом вызове).
2. **Ignition** — интерпретатор байткода. Запускается быстро и собирает **обратную связь о типах**: какие формы объектов и типы чисел видел каждый участок кода.
3. **Sparkplug** — быстрый неоптимизирующий компилятор в машинный код.
4. **Maglev** и **TurboFan** — оптимизирующие компиляторы для горячих функций. По собранным типам генерируют специализированный код: «здесь всегда целые числа», «здесь объект всегда такой формы».
5. **Деоптимизация**: если предположение нарушилось (пришла строка вместо числа), оптимизированный код выбрасывается и выполнение возвращается в интерпретатор.

## Скрытые классы

У каждого объекта есть **форма** (в V8 — Map, в литературе hidden class): набор свойств и смещения, где лежат их значения. Объекты с одинаковым набором полей, **добавленных в одинаковом порядке**, делят одну форму. Добавление свойства — переход в новую форму по дереву переходов.

## Inline cache

В каждом месте кода, где читается свойство (`o.x`), V8 запоминает: «для формы S поле x лежит в слоте k». Пока приходят объекты одной формы — **мономорфный** кэш: одна проверка и прямое чтение. Создай объекты разными способами и вызови `getX` на каждом:

Видно, что `{x, y}` и `{y, x}` — **разные формы**, хотя поля те же. А `delete` переводит объект в словарный режим, где каждое обращение — поиск по хеш-таблице.

## Что из этого следует для кода

- Инициализируй все поля **в конструкторе и в одном порядке**; не добавляй поля потом.
- Не используй `delete` на горячих объектах — присваивай `undefined` или `null`.
- Держи функции **мономорфными**: одна функция — объекты одной формы. Функция, которая принимает «что угодно», будет медленной.
- Не смешивай типы в массивах: массив только из целых (`PACKED_SMI_ELEMENTS`) быстрее, чем с дробными, а тот — быстрее, чем со смешанными. Дырявые массивы (`new Array(1000)` без заполнения) — медленнее плотных.
- TypeScript здесь помогает непреднамеренно: описанные интерфейсы подталкивают к стабильным формам.

<Takeaways>
- V8: Ignition (байткод + сбор типов) → Sparkplug → Maglev/TurboFan (оптимизация по типам) → **деоптимизация**, если предположение нарушено.
- **Скрытые классы (формы)**: одинаковые поля в одинаковом порядке → одна форма.
- **Inline cache**: мономорфный (быстро) → полиморфный → мегаморфный (словарь).
- Поля — в конструкторе и в одном порядке, без `delete`; функции мономорфные; массивы однотипные и плотные.
</Takeaways>
