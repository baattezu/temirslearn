CPU и GPU решают противоположные задачи. CPU — несколько мощных ядер, которые быстро выполняют **один сложный поток** инструкций: предсказание переходов, out-of-order, огромные кэши. GPU — тысячи простых ядер, которые выполняют **одну и ту же операцию над огромным массивом данных**. Нейросети, графика, физика — это как раз второй случай.

## Устройство GPU

На примере NVIDIA:

- **SM** (streaming multiprocessor) — аналог «ядра»; у H100 их 132.
- В SM — десятки-сотни арифметических блоков, **тензорные ядра** (умножение маленьких матриц за такт), регистры и быстрая **разделяемая память** (shared memory, ~200 КБ на SM).
- Потоки объединяются в **варпы по 32** — они выполняют одну инструкцию одновременно (SIMT: single instruction, multiple threads).
- **HBM** — видеопамять с пропускной способностью ~3 ТБ/с (у CPU — ~0.1–0.4 ТБ/с).

GPU **прячет задержку памяти количеством**: пока один варп ждёт данные, планировщик SM переключается на другой (переключение бесплатное — у каждого варпа свои регистры). CPU прячет задержку кэшами и спекуляцией.

## Почему нейросети живут на GPU

Почти вся работа трансформера — **умножение матриц**: проекции Q, K, V, attention, MLP. Это 2n³ операций над n² данными — каждый загруженный элемент используется n раз, и вычислители не простаивают в ожидании памяти.

## Узкие места

- **Пропускная способность памяти**, а не FLOPS. Генерация текста LLM по одному токену — это чтение всех весов модели на каждый токен; скорость ограничена HBM. Поэтому квантизация (меньше байт на вес) ускоряет инференс почти пропорционально.
- **PCIe** между CPU и GPU — ~64 ГБ/с. Перекладывать данные туда-обратно на каждом шаге — убить выигрыш.
- **Связь между GPU** (NVLink, InfiniBand) — для обучения больших моделей на тысячах карт.
- **Occupancy**: если на SM мало варпов (много регистров на поток, большие блоки shared memory), задержки памяти нечем прятать.

<Callout kind="tip" title="Арифметическая интенсивность">
Ключевая величина — сколько операций приходится на байт, прочитанный из памяти. Умножение больших матриц — сотни FLOP/байт: упирается в вычисления. Сложение двух векторов — 1/12 FLOP/байт: упирается в память, и GPU работает на малую долю мощности. Это и есть roofline-модель.
</Callout>

<Takeaways>
- CPU — мало мощных ядер для **сложного последовательного** кода; GPU — тысячи простых для **одинаковой работы над массивом**.
- Потоки GPU идут **варпами по 32** (SIMT); расхождение ветвлений = простой.
- GPU прячет задержку памяти **переключением между варпами**, CPU — кэшами и спекуляцией.
- Матрицы — идеал: много операций на байт. LLM-инференс по токену упирается в **пропускную способность HBM**.
- Узкие места: память, PCIe, связь между GPU, occupancy.
</Takeaways>
