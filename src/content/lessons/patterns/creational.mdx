Порождающие паттерны отвечают на вопрос: **кто и как создаёт объекты**. `new` — самая жёсткая зависимость в коде: написал `new StripeClient()` — и класс навсегда привязан к Stripe. Порождающие паттерны прячут создание за методом или объектом, чтобы его можно было менять.

## Factory Method и статические фабрики

Самая распространённая форма — **статический фабричный метод**. Блох в «Effective Java» ставит его первым советом книги: «Рассмотрите статические фабрики вместо конструкторов».

```java
List<String> xs = List.of("a", "b");         // вернёт оптимизированную реализацию под размер
Optional<User> u = Optional.ofNullable(found);
LocalDate d = LocalDate.of(2025, 3, 8);
BigInteger p = BigInteger.valueOf(42);        // может вернуть закэшированный объект
Money price = Money.of("1500.00", "KZT");
```

Чем фабрика лучше конструктора:
- **имя**: `Money.zero()`, `Duration.ofSeconds(5)` понятнее, чем `new Duration(5, 0)`;
- **может вернуть существующий объект** (кэш): `Integer.valueOf(100)`;
- **может вернуть подтип**: `List.of` возвращает разные внутренние классы для 0, 1, 2 и N элементов, а вызывающий видит просто `List`;
- **может отказаться создавать**: вернуть `Optional.empty()` или бросить понятную ошибку валидации.

Классический Factory Method из GoF — метод, который **наследник** переопределяет, чтобы решить, какой объект создать. Сегодня его чаще заменяет передача фабрики как функции: `Supplier<Connection>`.

## Builder

Когда у объекта много параметров, часть необязательных, конструктор превращается в загадку:

## Singleton

Гарантирует, что экземпляр класса один, и даёт к нему глобальную точку доступа. Самый известный и самый **критикуемый** паттерн:

- **это глобальное состояние** в красивой обёртке: кто угодно, откуда угодно может его менять;
- **скрытые зависимости**: по сигнатуре метода не видно, что он использует `Config.getInstance()`;
- **трудно тестировать**: синглтон нельзя подменить, и тесты влияют друг на друга через его состояние.

Если один экземпляр действительно нужен, в Java есть два хороших способа:

```java
enum IdGenerator {                      // Блох: лучший способ сделать синглтон
    INSTANCE;
    private final AtomicLong next = new AtomicLong();
    long next() { return next.incrementAndGet(); }
}
```

И главный: **пусть единственность обеспечивает контейнер**. Spring-бины по умолчанию существуют в одном экземпляре (scope singleton), но при этом внедряются через конструктор — зависимость видна, а в тесте подменяется. Это «синглтон без паттерна Singleton».

## Abstract Factory и DI

Abstract Factory — объект, который создаёт **семейство связанных объектов**: например, кнопки, поля и меню в одном стиле для Windows или macOS. В бэкенде эту роль почти всегда играет **DI-контейнер**: ты описываешь, какую реализацию использовать (профиль `prod` — `S3Storage`, профиль `test` — `InMemoryStorage`), а контейнер собирает граф объектов.

<Takeaways>
- Порождающие паттерны прячут `new`, самую жёсткую зависимость.
- **Статические фабрики** (`List.of`, `Optional.of`): имя, кэш, возврат подтипа, валидация.
- **Builder** — для объектов с многими параметрами; собирает неизменяемый объект и проверяет инварианты в `build()`.
- **Singleton** — глобальное состояние; если нужен один экземпляр — `enum` или, лучше, бин в DI-контейнере.
- **Abstract Factory** в бэкенде обычно заменяет DI-контейнер с профилями.
</Takeaways>
