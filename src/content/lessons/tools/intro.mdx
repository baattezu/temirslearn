Git, Docker и Kubernetes — три инструмента, без которых сегодня не обходится почти ни одна команда. Все три появились как ответ на конкретную боль, и у всех трёх за спиной история длиннее, чем кажется.

## Git: инструмент, написанный за две недели

До Git ядро Linux разрабатывали тысячи людей, и патчи присылали по почте. С 2002 года ядро жило в коммерческой системе **BitKeeper**, которую авторы бесплатно разрешили использовать сообществу. В 2005 году разрешение отозвали после конфликта.

Линус Торвальдс сел писать свою систему контроля версий. Требования у него были жёсткие: **распределённость** (у каждого полная история), **скорость** (применить сотни патчей за секунды) и **защита от порчи** (каждый объект проверяется хешем). Первую рабочую версию он сделал примерно за две недели, через пару месяцев на Git уже вели разработку ядра.

Ключевая идея Git — он хранит не дифы, а **снимки**, адресуемые хешем содержимого. Коммит — это снимок всего проекта плюс ссылка на родителя. Ветка — просто указатель на коммит. Поэтому ветки в Git почти бесплатные, а история — граф, который можно переписывать (rebase), не теряя объекты.

## Docker: «у меня работает»

Вечная боль: код работает на машине разработчика и падает на сервере. Другая версия Python, другая библиотека, другие настройки. Виртуальные машины решают это, но тяжело: своя ОС, гигабайты, минуты на старт.

Главное, что понимают не все: **контейнер — это обычный процесс Linux**, просто ядро показывает ему свою картину мира (namespaces) и ограничивает ресурсы (cgroups). Никакой отдельной ОС внутри нет.

## Kubernetes: опыт Google в открытом виде

Внутри Google с середины 2000-х работала система **Borg**: она раскладывала миллионы задач по машинам датацентров, перезапускала упавшие, следила за ресурсами. В 2014 году Google выпустила открытый проект по мотивам Borg — **Kubernetes** (греч. «рулевой»), и через год отдала его в фонд CNCF.

Идея Kubernetes — **декларативность**: ты описываешь, *что* должно быть («3 копии сервиса с таким образом, доступные по такому имени»), а контроллеры в бесконечном цикле приводят реальность к описанию. Упала машина — поды переедут, вырос трафик — добавятся реплики.

## Как они связаны

Три инструмента — три шага одного пути кода:

1. **Git** хранит код и его историю → CI собирает его при каждом коммите.
2. **Docker** упаковывает результат вместе со всеми зависимостями в образ.
3. **Kubernetes** запускает образы на кластере и держит их живыми.

## Карта трека

1. **Git изнутри** — объекты, DAG, что на самом деле делают merge и rebase.
2. **Docker** — namespaces, cgroups, слои и кэш сборки.
3. **Kubernetes** — reconcile-цикл, поды, пробы и выкатка.

<Takeaways>
- **Git** (Линус, 2005) — написан за пару недель после потери BitKeeper: распределённость, скорость, снимки по хешу содержимого.
- **Docker** (2013) — не новая изоляция, а удобная упаковка механизмов ядра (chroot → jails → namespaces + cgroups). Контейнер — процесс Linux.
- **Kubernetes** (2014) — открытая версия идей Borg: декларативное состояние и reconcile-циклы.
- Вместе: код в Git → образ в Docker → запуск в Kubernetes.
</Takeaways>
