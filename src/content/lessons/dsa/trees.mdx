Деревья на собесе — это рекурсия в чистом виде. Почти любая задача решается вопросом: «что я верну из поддерева, и как собрать ответ для узла из ответов детей?»

## Двоичное дерево поиска

**BST**: для каждого узла все ключи левого поддерева меньше, правого — больше. Поиск, вставка и удаление идут по одному пути от корня, поэтому стоят **O(высоты)**. Если дерево сбалансировано, высота ≈ log₂ n; если нет — вплоть до n.

<TreeViz />

Попробуй «10…70 по порядку» с выключенной балансировкой: дерево выродится в список высотой 7, и поиск станет O(n). Включи AVL и повтори — после каждой вставки дерево делает повороты, и высота остаётся логарифмической.

## Удаление: три случая

1. **Лист** — просто убираем.
2. **Один ребёнок** — ставим ребёнка на место узла.
3. **Два ребёнка** — заменяем ключ узла на **преемника** (минимум правого поддерева) и удаляем преемника из правого поддерева. У преемника нет левого ребёнка, поэтому это сводится к случаю 1 или 2.

## Сбалансированные деревья

| Дерево | Инвариант | Где живёт |
|---|---|---|
| **AVL** | высоты поддеревьев отличаются ≤ 1 | быстрый поиск, больше поворотов при вставке |
| **Красно-чёрное** | на любом пути одинаково чёрных узлов, красный не идёт за красным | `TreeMap` в Java, `std::map` в C++, бакеты HashMap |
| **B-дерево** | узел = страница, сотни ключей | индексы баз данных, файловые системы |

На собесе обычно хватает: «TreeMap — красно-чёрное дерево, все операции O(log n), ключи упорядочены — есть `floorKey`, `ceilingKey`, `subMap`». А HashMap даёт O(1), но без порядка.

## Обходы

- **in-order** (левое, узел, правое) — в BST выдаёт ключи **отсортированными**. Проверка «является ли дерево BST» = in-order строго возрастает.
- **pre-order** (узел, левое, правое) — сериализация дерева, копирование.
- **post-order** (левое, правое, узел) — когда ответ узла зависит от детей: высота, удаление, сумма поддерева.
- **BFS по уровням** — очередь; «правый вид», «уровни зигзагом», минимальная глубина.

## Шаблон рекурсии

```python
def height(node):
    if node is None:
        return 0                          # база
    return 1 + max(height(node.left), height(node.right))
```

Сложнее — когда из поддерева нужно вернуть **больше одного значения**. Диаметр дерева: из каждого узла возвращаем высоту, а попутно обновляем глобальный ответ `left + right`.

```python
def diameter(root):
    best = 0
    def h(n):
        nonlocal best
        if not n: return 0
        l, r = h(n.left), h(n.right)
        best = max(best, l + r)           # путь через этот узел
        return 1 + max(l, r)              # а наверх отдаём только высоту
    h(root)
    return best
```

<Callout kind="warn" title="Глубина рекурсии">
На вырожденном дереве из 10⁵ узлов рекурсия упадёт: в Python лимит ~1000, в Java — переполнение стека. Если дерево может быть несбалансированным, перепиши обход итеративно со своим стеком.
</Callout>

<Takeaways>
- BST: поиск, вставка, удаление — **O(высоты)**; несбалансированное вырождается в список.
- AVL и красно-чёрные деревья держат высоту **O(log n)** поворотами. TreeMap = красно-чёрное.
- Удаление с двумя детьми — через **преемника**.
- in-order = сортировка; post-order — когда узлу нужны ответы детей; BFS — по уровням.
- Шаблон: база для `null` + сборка из ответов детей; глобальный ответ — отдельно от возвращаемого значения.
</Takeaways>
