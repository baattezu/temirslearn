O-нотация говорит, что проход по массиву и по связному списку — одинаковые O(n). На практике список на порядок медленнее. Причина — не в алгоритме, а в том, **как данные лежат в памяти** и как процессор их читает.

## Память читается кэш-линиями

Процессор никогда не читает из RAM один байт или одно число. Он загружает **кэш-линию** — 64 байта подряд — и кладёт её в кэш L1. Обращение к L1 стоит ~1 нс, к RAM — ~80–100 нс. Разница в сто раз, поэтому скорость кода почти целиком определяется тем, сколько раз пришлось сходить в RAM.

- **Массив** лежит в памяти подряд. Одна линия даёт 8 элементов `long`, а **аппаратный префетчер** видит последовательный доступ и подгружает следующие линии заранее.
- **Связный список** — узлы, выделенные в разное время и разбросанные по куче. Каждый переход по `next` — прыжок в случайное место, почти всегда промах. Префетчер бессилен: адрес следующего узла становится известен только после чтения текущего.

## Динамический массив: откуда амортизированное O(1)

`ArrayList`, `std::vector`, `list` в Python — это массив фиксированной **ёмкости** (capacity) плюс счётчик **размера** (size). Пока место есть, `append` — просто запись в следующую ячейку. Когда место кончилось, выделяется новый буфер **в k раз больше**, и все элементы копируются.

Отдельный append может стоить O(n), но если ёмкость растёт **геометрически**, суммарное число копирований за n вставок не больше 2n. Это и есть **амортизированное O(1)**. Попробуй разные стратегии роста:

С ростом «+4» копирований становится n²/8: каждые 4 вставки копируется весь массив. Отсюда правило: рост всегда **мультипликативный**. В Java ArrayList растёт в 1.5 раза, в C++ libstdc++ — в 2, в Python — примерно в 1.125 плюс константа.

Если размер известен заранее, передай его сразу: `new ArrayList<>(n)`, `v.reserve(n)`. Это уберёт все копирования.

## Стоимость операций

| Операция | Массив | Динамический массив | Связный список |
|---|---|---|---|
| доступ по индексу | O(1) | O(1) | O(n) |
| append в конец | — | O(1) амортизированно | O(1) |
| вставка в начало | O(n) | O(n) | O(1) |
| вставка в середину (по индексу) | O(n) | O(n) | O(n) до места + O(1) |
| проход по всем | O(n), быстро | O(n), быстро | O(n), промах на каждом узле |
| память на элемент | значение | значение + запас до 2× | значение + 1–2 указателя + заголовок |

## Где списки всё-таки нужны

- **LRU-кэш**: хеш-таблица + двусвязный список. Узел достаётся из таблицы за O(1), и его можно переставить в голову за O(1) без поиска.
- **Очередь без копирования** при огромных объёмах — но чаще используют кольцевой буфер (`ArrayDeque`), который снова массив.
- **Интрузивные списки** в ядре ОС и аллокаторах, где узел уже является частью объекта.

<Takeaways>
- Процессор читает память **кэш-линиями по 64 Б**; L1 ~1 нс, RAM ~100 нс.
- Массив — подряд: 8 `long` за одну загрузку + префетчер. Список — **промах на каждом узле**.
- Динамический массив растёт **геометрически** → append амортизированно O(1), суммарно ≤ 2n копирований.
- Рост «+константа» даёт O(n²) копирований. Если размер известен — `reserve` / `new ArrayList<>(n)`.
- По умолчанию — массив. Список — когда нужно O(1) удаление узла, на который уже есть ссылка (LRU).
</Takeaways>
