Сортировку почти никогда не пишут руками — но на собесе спрашивают, как работают быстрая и слияние, почему встроенная сортировка в Java разная для примитивов и объектов и что такое стабильность. А ещё сортировка — первый шаг в огромном числе решений.

## Три сортировки на одном массиве

<SortViz />

- **Вставками**: каждый следующий элемент «просачивается» на своё место. O(n²) в худшем случае, но O(n) на почти отсортированных данных и очень быстрая на маленьких массивах — у неё нет накладных расходов.
- **Слиянием**: делим пополам, сортируем половины, сливаем. Всегда O(n log n), **стабильна**, но требует O(n) дополнительной памяти.
- **Быстрая**: выбираем опорный элемент, разбиваем на «меньше» и «больше», рекурсия. В среднем O(n log n) и очень быстрая на практике (на месте, хорошо с кэшем), но в худшем случае O(n²) — посмотри, что с ней делает уже отсортированный массив при опорном «последний элемент».

## Стабильность

**Стабильная** сортировка сохраняет порядок равных элементов. Это важно, когда сортируют по нескольким ключам по очереди: отсортировал заказы по дате, потом стабильно по статусу — внутри каждого статуса они остались по дате.

## Что внутри стандартных библиотек

| Где | Что | Почему |
|---|---|---|
| Java `Arrays.sort(int[])` | Dual-Pivot Quicksort | примитивы: стабильность не нужна, важна скорость |
| Java `Arrays.sort(Object[])`, `List.sort` | **TimSort** | объекты: нужна стабильность |
| Python `sorted`, `list.sort` | TimSort (Powersort с 3.11) | стабильна, быстра на частично упорядоченных данных |
| C++ `std::sort` | Introsort | quicksort, который при глубокой рекурсии переключается на heapsort — гарантирует O(n log n) |

**TimSort** находит в данных уже упорядоченные куски (runs), добивает короткие до минимальной длины вставками и сливает их. Поэтому реальные данные, которые часто частично отсортированы, сортируются быстрее n log n.

## Нижняя граница и обход её

Любая сортировка **сравнениями** в худшем случае требует Ω(n log n) сравнений: n! перестановок, а каждое сравнение даёт один бит информации. Обойти можно, только не сравнивая:

- **Подсчётом** (counting sort) — ключи из небольшого диапазона: O(n + k).
- **Поразрядная** (radix sort) — по цифрам/байтам: O(n · длина ключа).
- **Блочная** (bucket sort) — равномерно распределённые ключи.

## Сортировка в задачах

- «Найти пары / дубликаты / пересечения» — отсортируй, потом два указателя.
- «Объединить интервалы» — сортировка по началу, потом один проход (в «Задачах» — Merge Intervals).
- «Top-k» — не сортируй всё: куча или quickselect.
- Компаратор в Java: `Comparator.comparing(Order::status).thenComparing(Order::createdAt)`. Не пиши `a - b` для int — переполнение. Используй `Integer.compare`.

<Takeaways>
- **Вставками** — O(n²), но лучшая на маленьких и почти отсортированных массивах.
- **Слиянием** — всегда O(n log n), стабильна, O(n) памяти. **Быстрая** — O(n log n) в среднем, на месте, худший O(n²) → случайный pivot / introsort.
- **Стабильность** важна для сортировки по нескольким ключам.
- Java: примитивы — dual-pivot quicksort, объекты — **TimSort** (стабильная, использует готовые runs).
- Сравнения: нижняя граница n log n; counting/radix обходят её на ограниченных ключах.
</Takeaways>
