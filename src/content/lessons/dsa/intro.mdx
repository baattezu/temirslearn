Алгоритм — это **точный рецепт**: конечная последовательность шагов, которая для любого допустимого входа даёт ответ. Слово старше компьютеров на тысячу лет, а самому известному алгоритму — больше двух тысяч.

## Евклид и аль-Хорезми

Около 300 года до н. э. **Евклид** описал, как найти наибольший общий делитель двух чисел: вычитай меньшее из большего (или бери остаток), пока не получишь ноль. Этот алгоритм работает до сих пор — в каждом RSA-шифровании, в упрощении дробей, в `Math.gcd`.

```java
long gcd(long a, long b) {
    while (b != 0) { long t = a % b; a = b; b = t; }
    return a;
}
// gcd(1071, 462): 1071 % 462 = 147 → 462 % 147 = 21 → 147 % 21 = 0 → ответ 21
```

Слово «алгоритм» — искажённое имя персидского учёного **аль-Хорезми** (IX век): его книга о вычислениях индийскими цифрами в латинском переводе начиналась словами «Dixit Algorizmi» — «сказал аль-Хорезми». Его же книга «аль-джабр» дала имя алгебре.

## Почему «как» важнее «что»

Пока компьютеры были медленными, а задачи — маленькими, было неважно, как считать. Потом данные выросли, и выяснилось, что **выбор алгоритма важнее скорости железа**. Сортировка миллиона чисел «пузырьком» — это ~10¹² сравнений, а слиянием — ~2·10⁷. Разница в 50 000 раз, и никакой процессор её не компенсирует.

## Зачем это спрашивают на собесах

Честно: в обычной работе редко пишешь красно-чёрное дерево. Но алгоритмическая секция проверяет вещи, которые нужны каждый день:

- **Умеешь ли оценить стоимость кода** до того, как он упал в проде: «тут вложенный цикл по заказам и товарам — при росте это O(n·m)».
- **Знаешь ли инструменты**: хеш-таблица вместо поиска в списке, куча для top-k, очередь для BFS. Половина оптимизаций в реальном коде — это «заменить список на `HashMap`».
- **Как ты думаешь вслух**: перебор → узкое место → оптимизация → краевые случаи → сложность.

## Структуры данных — это про память

Главная мысль трека: структура данных — это **способ разложить данные в памяти** так, чтобы нужные операции были дешёвыми. Массив дешёв для обхода и индекса, но дорог для вставки в начало. Хеш-таблица даёт поиск за O(1), но не хранит порядок. B-tree медленнее хеша на точечный поиск, но умеет диапазоны и живёт на диске. Каждая структура — компромисс, и в уроках ты увидишь, как они лежат в памяти байт за байтом.

## Карта трека

1. **Сложность** — что реально влезет в секунду при данном n.
2. **Массивы, списки и кэш** — почему O(1) бывает разным.
3. **Хеш-таблицы**, **два указателя и окно**, **бинарный поиск** — базовые приёмы.
4. **Деревья, кучи, графы, стек и очередь, сортировки** — основные структуры.
5. **DP, trie, union-find, перебор с возвратом** — продвинутые паттерны.

Задачи для каждого паттерна — во вкладке «Задачи», судья работает прямо в браузере.

<Takeaways>
- Алгоритм — точный конечный рецепт. Старейший живой — **Евклидов НОД**; слово — от имени **аль-Хорезми**.
- При больших данных **выбор алгоритма важнее железа**. Кнут сделал анализ алгоритмов наукой, отсюда O-нотация.
- Структура данных — **способ разложить данные в памяти** под нужные операции; всегда компромисс.
- На собесе проверяют умение оценить стоимость кода, знание инструментов и ход мысли вслух.
