Куча (приоритетная очередь) отвечает на один вопрос: «дай минимальный элемент» — за O(1), а добавление и удаление стоят O(log n). На ней стоят top-k, слияние k списков, медиана потока, Дейкстра и планировщики задач.

## Дерево, которое на самом деле массив

Двоичная куча — **полное** двоичное дерево: все уровни заполнены, последний — слева направо. Такое дерево укладывается в массив без единого указателя:

- родитель `i` — это `(i − 1) / 2`;
- дети — `2i + 1` и `2i + 2`.

Инвариант min-кучи: **родитель ≤ детей**. Значит, минимум всегда в `a[0]`. Порядка между братьями нет — куча не отсортирована.

## Операции

- **push**: кладём в конец массива и **поднимаем** (sift-up), меняя с родителем, пока он больше. Не больше высоты шагов — O(log n).
- **pop**: забираем `a[0]`, на его место ставим последний элемент и **опускаем** (sift-down), меняя с меньшим из детей. O(log n).
- **heapify** массива: опускаем все внутренние узлы, начиная с последнего. Кажется, что это n · log n, но на самом деле **O(n)**: большинство узлов внизу, и опускаться им некуда. Половина узлов — листья, четверть опускается на 1 уровень, восьмая — на 2…

## Top-k: куча размера k

«Найди k самых больших из n» (или из бесконечного потока):

```python
import heapq
def top_k(nums, k):
    h = []                      # min-куча из k лучших на данный момент
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)    # выкидываем самого слабого из лучших
    return h
```

Это O(n log k) по времени и O(k) памяти. Для k много меньше n — почти линейно. Обрати внимание: для k **самых больших** нужна **min**-куча, потому что выкидываем минимальный из кандидатов.

Альтернатива — **quickselect** за O(n) в среднем, но он требует весь массив в памяти и портит порядок.

## Где ещё куча

| Задача | Как |
|---|---|
| Слияние k отсортированных списков | куча из голов списков, O(N log k) |
| Медиана потока | max-куча для меньшей половины + min-куча для большей |
| Дейкстра | min-куча по расстоянию |
| Расписание / таймеры | min-куча по времени срабатывания |
| Встречи: сколько нужно комнат | сортировка по началу + min-куча по концу |

В Java — `PriorityQueue` (min по умолчанию, max — `new PriorityQueue<>(Comparator.reverseOrder())`), в Python — `heapq` (только min; для max кладут `-x`).

<Callout kind="warn" title="Ловушки">
`PriorityQueue.remove(obj)` и `contains` — O(n): куча не умеет искать. Итерация по `PriorityQueue` **не** идёт в порядке приоритета. А в Дейкстре вместо «уменьшить ключ» обычно кладут дубликат и пропускают устаревшие записи при извлечении.
</Callout>

<Takeaways>
- Куча — **полное дерево в массиве**: родитель `(i−1)/2`, дети `2i+1`, `2i+2`.
- Min-куча: родитель ≤ детей, минимум в `a[0]`. Братья не упорядочены.
- push — sift-up, pop — последний в корень + sift-down: оба **O(log n)**; peek — O(1).
- **heapify — O(n)**, а не n log n.
- Top-k самых больших — **min**-куча размера k: O(n log k).
</Takeaways>
