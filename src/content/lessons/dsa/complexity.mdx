Сложность алгоритма — это не про точное время, а про то, **как растёт работа с ростом входа**. На собесе и в задачах важен практичный навык: по ограничениям на `n` сразу понять, какое решение пройдёт, а какое нет.

## O-нотация в одном абзаце

`O(f(n))` означает: при больших n работа растёт не быстрее, чем `c · f(n)` для какой-то константы. Константы и младшие слагаемые отбрасываются: `3n² + 100n + 7` — это `O(n²)`. Поэтому O говорит о **масштабировании**, а не о скорости на маленьких входах: на n = 10 сортировка вставками обгоняет быструю.

## Двигай n

Грубое правило: простая операция (сравнение, сложение, обращение к массиву) — ~10⁸ в секунду на Java/C++/Go и ~10⁷ на Python.

<Growth />

Обрати внимание: при n = 10⁵ решение за O(n²) — это 10¹⁰ операций, то есть ~100 секунд. Типичное ограничение «n ≤ 10⁵» в задаче — прямая подсказка, что нужно O(n log n) или лучше.

## Как оценить сложность кода

- **Вложенные циклы** по n — умножай: два вложенных — O(n²).
- **Цикл, где индекс делится или умножается** (`i *= 2`, бинарный поиск) — O(log n).
- **Рекурсия**: число вызовов × работа в вызове. Наивный Фибоначчи ветвится на 2 → O(2ⁿ); с мемоизацией каждое состояние считается один раз → O(n).
- **Сортировка** — почти всегда O(n log n), не забывай её в оценке.
- **Хеш-таблица** — O(1) в среднем на операцию, но O(n) в худшем случае.
- **Строки**: склеивание в цикле `s += x` в Java/Python может давать O(n²) из-за копирования.

## Амортизация и средний случай

Не все O одинаковые:

| Вид | Пример | Смысл |
|---|---|---|
| худший случай | бинарный поиск O(log n) | гарантия на каждую операцию |
| амортизированно | append в ArrayList O(1) | редкие дорогие операции «размазаны» по дешёвым |
| в среднем | HashMap.get O(1) | при хорошем хеше; в худшем — O(n) или O(log n) |
| ожидаемо | quicksort со случайным pivot O(n log n) | по случайности алгоритма |

## Память тоже сложность

Рекурсия глубиной n занимает O(n) стека — в Python по умолчанию это падение после ~1000 уровней, в Java — `StackOverflowError` на десятках тысяч. DP-таблица n × m — это O(nm) памяти, но часто хватает двух строк: O(m).

<Callout kind="tip" title="Как говорить на собесе">
Называй сложность **сразу** для своего решения — и по времени, и по памяти, — и объясняй, откуда она: «сортировка — n log n, дальше один проход — n, итого O(n log n) по времени и O(1) дополнительной памяти, если сортируем на месте». Потом спроси себя вслух, можно ли лучше, и назови нижнюю границу: «прочитать вход — уже O(n), поэтому линейное решение оптимально».
</Callout>

<Takeaways>
- O — про **рост**, константы отбрасываются. ~10⁸ простых операций/с (Python ~10⁷).
- По ограничению n выбирай класс: 10⁵ → O(n log n), 10³ → O(n²), 20 → O(2ⁿ).
- Вложенные циклы умножаются, деление пополам даёт log, рекурсия = вызовы × работа.
- Различай худший, **амортизированный** и средний случай.
- Память и стек рекурсии — тоже часть ответа.
</Takeaways>
