Бинарный поиск знают все, а пишут без ошибок единицы: путаница с `lo`, `hi`, `<` или `<=`, `mid - 1` или `mid`, бесконечный цикл на двух элементах. Лечится одним приёмом — **писать от инварианта**, а не подбирать границы.

## Инвариант вместо «подгонки»

Выбери, что означают `lo` и `hi`, и сохраняй это на каждом шаге. Самая надёжная форма — **lower_bound** на полуоткрытом интервале `[lo, hi)`:

- всё **левее** `lo` — меньше `x`;
- всё **от** `hi` **и правее** — не меньше `x`;
- в `[lo, hi)` — то, что ещё не проверено.

Когда интервал пуст (`lo == hi`), граница найдена: `lo` — индекс первого элемента `≥ x`, или `n`, если такого нет.

```python
def lower_bound(a, x):
    lo, hi = 0, len(a)           # [lo, hi) — ещё не проверено
    while lo < hi:
        mid = (lo + hi) // 2      # mid < hi, поэтому a[mid] существует
        if a[mid] < x:
            lo = mid + 1          # a[mid] и всё левее < x
        else:
            hi = mid              # a[mid] >= x — может быть ответом
    return lo
```

Каждая строка следует из инварианта. `hi = mid`, а не `mid - 1`, потому что `a[mid]` может быть ответом и должен остаться «справа от границы». Цикл всегда сужается, потому что `mid < hi`.

## Через lower_bound выражается всё

| Задача | Решение |
|---|---|
| есть ли `x` | `i = lower_bound(a, x)`, проверить `i < n and a[i] == x` |
| первое вхождение `x` | `lower_bound(a, x)` |
| последнее вхождение `x` | `lower_bound(a, x + 1) - 1` (для целых) |
| сколько раз встречается `x` | `lower_bound(a, x + 1) - lower_bound(a, x)` |
| куда вставить, сохранив порядок | `lower_bound(a, x)` |

В Python это `bisect.bisect_left`, в C++ — `std::lower_bound`, в Java — `Collections.binarySearch` (но он возвращает **любое** вхождение, а не первое).

## Поиск по ответу

Бинарный поиск работает не только по массиву, а по **любому монотонному предикату**: если `ok(k)` ложно до какого-то порога и истинно после, порог находится за `O(log диапазона)` проверок.

Пример: «минимальная скорость, при которой Коко съест все бананы за h часов». Чем выше скорость, тем быстрее — предикат монотонный. Ищем первую скорость, для которой `ok(speed)` истинно, тем же шаблоном.

<Callout kind="warn" title="Переполнение">
В Java и C++ `(lo + hi) / 2` переполняется, когда индексы близки к `2^31`. Пиши `lo + (hi - lo) / 2`. В Python целые не переполняются.
</Callout>

<Takeaways>
- Пиши от **инварианта**: `[lo, hi)`, левее `lo` — меньше `x`, от `hi` — не меньше.
- `while lo < hi`, `lo = mid + 1` или `hi = mid` — без `±1` наугад, без бесконечных циклов.
- Через lower_bound выражаются поиск, первое и последнее вхождение, подсчёт, точка вставки.
- Работает для любого **монотонного предиката** — «поиск по ответу».
- `O(log n)`: на миллион элементов — 20 сравнений.
</Takeaways>
