Динамическое программирование пугает названием, но сводится к одной мысли: **если подзадачи повторяются — посчитай каждую один раз и запомни**. Всё остальное — техника: как выбрать состояние, переход и порядок вычисления.

## От рекурсии к DP

Числа Фибоначчи: `f(n) = f(n−1) + f(n−2)`. Наивная рекурсия считает `f(n−2)` дважды, `f(n−3)` трижды и т. д. — O(2ⁿ) вызовов. Но различных подзадач всего n.

```python
from functools import cache

@cache                                  # мемоизация: сверху вниз
def f(n):
    return n if n < 2 else f(n - 1) + f(n - 2)

def f_table(n):                         # табуляция: снизу вверх
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b                 # храним только два последних — O(1) памяти
    return a
```

Оба варианта — O(n). Мемоизация проще написать, табуляция не упирается в глубину рекурсии и позволяет сжать память.

## Четыре вопроса к любой DP-задаче

1. **Состояние**: что значит `dp[i]` или `dp[i][j]`? Формулируй словами: «длина LCS префиксов `A[:i]` и `B[:j]`».
2. **Переход**: как `dp[i][j]` выражается через меньшие состояния?
3. **База**: значения для пустых префиксов, нуля, первого элемента.
4. **Порядок**: в каком порядке заполнять, чтобы зависимости были уже посчитаны. И где лежит ответ.

## Таблица на примере LCS

Наибольшая общая подпоследовательность двух строк. Состояние — `dp[i][j]`, длина LCS первых `i` символов `A` и первых `j` символов `B`. Переход:

- если `A[i−1] == B[j−1]` — этот символ входит в LCS: `dp[i][j] = dp[i−1][j−1] + 1`;
- иначе выкидываем последний символ одной из строк: `dp[i][j] = max(dp[i−1][j], dp[i][j−1])`.

После заполнения ответ восстанавливается обратным ходом из правого нижнего угла: на совпадении — по диагонали, иначе — туда, где значение больше.

Сложность — O(n·m) по времени. По памяти тоже O(n·m), но если нужна только длина, хватит **двух строк** таблицы: каждая строка зависит только от предыдущей.

## Классы задач

| Класс | Состояние | Примеры |
|---|---|---|
| Линейная | `dp[i]` — ответ для префикса | Climbing Stairs, House Robber, LIS за O(n²) |
| Две последовательности | `dp[i][j]` — префиксы обеих | LCS, Edit Distance, Regex Matching |
| Рюкзак | `dp[i][w]` — первые i предметов, вес w | Coin Change, Partition Equal Subset Sum |
| На отрезках | `dp[l][r]` — подотрезок | Burst Balloons, Matrix Chain |
| На деревьях | ответ узла из ответов детей | House Robber III, диаметр |
| По маскам | `dp[mask]` — подмножество | TSP для n ≤ 20 |

<Callout kind="tip" title="На собесе">
Начни с рекурсии с мемоизацией — её проще объяснить и проверить. Назови состояние словами, переход формулой, базу и сложность «число состояний × работа на переход». Если спросят про память — покажи, что строка зависит только от предыдущей, и сожми таблицу.
</Callout>

<Takeaways>
- DP = **повторяющиеся подзадачи** + оптимальная подструктура → считаем каждую один раз.
- Мемоизация (сверху вниз) или табуляция (снизу вверх) — одна и та же асимптотика.
- Четыре вопроса: **состояние, переход, база, порядок**.
- Сложность = число состояний × стоимость перехода. Память часто сжимается до одной-двух строк.
- Ответ восстанавливается обратным ходом по таблице.
</Takeaways>
