В Python всё — объект: числа, функции, классы, модули. А переменная — не ячейка памяти, а **имя, привязанное к объекту**. Из этой одной идеи следуют почти все «странности» языка: изменяемые аргументы по умолчанию, `is` против `==`, «почему список изменился, я же его не трогал».

## Имена и объекты

У каждого объекта есть **идентичность** (`id()` — адрес в CPython), **тип** и **значение**. Присваивание `b = a` не копирует объект — оно вешает на тот же объект второй ярлык. Пройди по шагам:

Правила:

- **изменяемые** объекты (`list`, `dict`, `set`, свои классы) можно менять на месте — это увидят все имена, ссылающиеся на объект;
- **неизменяемые** (`int`, `str`, `tuple`, `frozenset`) нельзя — любая «модификация» создаёт новый объект;
- аргументы передаются **ссылкой на объект** (call by sharing): функция может изменить переданный список, но не может перепривязать имя вызывающего.

<Callout kind="warn" title="Изменяемый аргумент по умолчанию">
`def add(x, items=[])` — список создаётся **один раз**, при определении функции, и живёт между вызовами. Второй вызов увидит элементы первого. Пиши `items=None` и `if items is None: items = []`.
</Callout>

## Как CPython хранит объекты

Каждый объект начинается с заголовка `PyObject`: **счётчик ссылок** (`ob_refcnt`) и указатель на тип. Поэтому `int` в Python занимает 28 байт, а не 4, и список из миллиона чисел — это миллион отдельных объектов плюс массив указателей на них. Для чисел в больших объёмах — `array` или NumPy, где данные лежат подряд.

**Сборка мусора** в CPython двухуровневая:

1. **Подсчёт ссылок**: когда счётчик падает до нуля, объект освобождается сразу и детерминированно.
2. **Циклический сборщик** (модуль `gc`) периодически ищет циклы — объекты, ссылающиеся друг на друга, недостижимые снаружи.

## Атрибуты и поиск

`obj.attr` — это не чтение поля, а целый протокол:

1. Ищем `attr` в классе и его родителях по **MRO** (порядку разрешения методов — линеаризация C3 при множественном наследовании). Если найден **data-дескриптор** (`property`, `__set__`) — он побеждает.
2. Иначе — `obj.__dict__`.
3. Иначе — не-data дескриптор или обычный атрибут класса (так методы превращаются в bound methods: функция — это дескриптор).
4. Иначе — `__getattr__`.

`__slots__` убирает `__dict__` у экземпляров: меньше памяти (на миллионах объектов — в разы) и быстрее доступ, но нельзя добавлять новые атрибуты.

## Хешируемость

Ключ `dict` и элемент `set` должен быть **хешируемым**: `__hash__` не меняется за время жизни и согласован с `__eq__`. Поэтому `list` не может быть ключом, а `tuple` — может, если все его элементы хешируемы. `dataclass(frozen=True)` даёт хешируемый неизменяемый класс.

<Takeaways>
- Переменная — **имя**, привязанное к объекту; присваивание не копирует.
- Изменяемые объекты меняются на месте — это видно через все имена; неизменяемые — только заменяются.
- Аргументы — **ссылкой на объект**; изменяемый аргумент по умолчанию создаётся один раз.
- `==` — значение, `is` — идентичность; маленькие int (−5…256) кэшированы.
- Память: каждый объект с заголовком (refcount + тип); GC = подсчёт ссылок + поиск циклов.
- Поиск атрибута: дескрипторы, `__dict__`, MRO; `__slots__` экономит память.
</Takeaways>
