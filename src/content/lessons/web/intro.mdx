Двадцать лет назад фронтенд считали «вёрсткой»: HTML, немного CSS и пара скриптов на jQuery. Сегодня это отдельная инженерия со своими компиляторами, системами типов, архитектурой состояния и метриками производительности. Каждый виток этой истории решал одну боль: **как держать интерфейс в синхронизации с данными**, когда приложение растёт.

## Главная идея React

До React интерфейс менялся **императивно**: пришли данные — найди элемент, поменяй текст, добавь класс, удали строку из таблицы. В большом приложении десятки таких мест, и рано или поздно интерфейс показывает не то, что лежит в данных.

React предложил другую модель: **UI = f(state)**. Ты пишешь функцию, которая по состоянию возвращает описание интерфейса. Состояние поменялось — функция вызывается заново, React сравнивает новое описание со старым (reconciliation) и сам вносит в DOM минимальные изменения.

```tsx
function Cart({ items }: { items: Item[] }) {
  const total = items.reduce((s, i) => s + i.price, 0);
  return (
    <div>
      {items.length === 0 ? <p>Корзина пуста</p> : items.map((i) => <Row key={i.id} item={i} />)}
      <b>Итого: {total}</b>
    </div>
  );
}
// нет «найди элемент и поменяй» — только «как выглядит при таких данных»
```

Это та же идея, что декларативность в SQL и Kubernetes: описываешь **что**, а не **как**.

## Почему TypeScript победил

JavaScript создавался для маленьких скриптов: динамические типы, `undefined is not a function` в проде. Когда фронтенд-кодовые базы выросли до сотен тысяч строк, переименовать поле стало страшно. **TypeScript** (Microsoft, 2012, ведущий архитектор — Андерс Хейлсберг, автор C#) добавил статические типы, которые полностью стираются при компиляции в обычный JS. Можно внедрять постепенно, файл за файлом. Сегодня почти любой серьёзный фронтенд пишут на TS.

## Чем занят фронтенд-инженер сегодня

- **Состояние и данные**: что хранить локально, что — в кэше запросов, как не допустить гонок и рассинхрона.
- **Производительность**: Core Web Vitals — скорость загрузки, отклик на действия, стабильность вёрстки.
- **Типы и архитектура**: компоненты, модули, дизайн-системы.
- **Доступность**: интерфейс для людей с экранными читалками и клавиатурой.
- **Сеть и сборка**: что грузить сразу, что потом, как кэшировать.

<Takeaways>
- Фронтенд прошёл путь: страницы → **AJAX** → **jQuery** (ручная правка DOM) → фреймворки → **React** → TypeScript и SSR.
- Главная боль — **синхронизация интерфейса с данными**. Ответ React — **UI = f(state)**, декларативность.
- **TypeScript** — типы поверх JS, стираются при компиляции; стандарт для больших кодовых баз.
- Фронтенд-инженер сегодня отвечает за состояние, производительность, типы, доступность и доставку кода.
