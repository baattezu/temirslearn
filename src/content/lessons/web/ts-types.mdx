TypeScript — это не «JavaScript с аннотациями», а система, которая **вычисляет** типы: сужает их по проверкам в коде, выводит из значений и умеет выражать сложные зависимости. Его сила — в том, чтобы сделать некорректные состояния **непредставимыми**.

## Структурная типизация

TypeScript сравнивает типы по **форме**, а не по имени. Объект подходит к интерфейсу, если у него есть нужные поля нужных типов, — неважно, как он был объявлен. Удобно, но иногда нужно отличать «одинаковые по форме» значения (`UserId` и `OrderId` — оба `string`). Для этого есть **брендированные типы**: `type UserId = string & { readonly __brand: "UserId" }`.

## Сужение типов

Внутри ветки `if` / `switch` компилятор уточняет тип переменной по проверке:

- `typeof x === "string"`, `x instanceof Date`, `"field" in x`;
- проверка на `null` / `undefined`, `Array.isArray`;
- **дискриминированные объединения** — общее поле-литерал (`kind`, `type`, `status`) у всех вариантов;
- свои предикаты: `function isUser(x): x is User`.

## Делай некорректные состояния непредставимыми

Вместо:

```ts
type Request = { loading: boolean; data?: User; error?: string };
// можно случайно: loading: true и одновременно data и error
```

пиши:

```ts
type Request =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "ok"; data: User }
  | { status: "error"; error: string };
```

Теперь `data` доступен только там, где `status === "ok"`, а забыть обработать новое состояние не даст проверка полноты через `never`.

## Инструменты системы типов

- **Дженерики**: `function first<T>(xs: T[]): T | undefined` — тип связывает вход и выход.
- **`keyof` и индексные типы**: `function get<T, K extends keyof T>(o: T, k: K): T[K]`.
- **Утилиты**: `Partial`, `Required`, `Pick`, `Omit`, `Record`, `ReturnType`, `Awaited`.
- **Условные типы**: `T extends string ? A : B`; с `infer` — извлечь часть типа.
- **Шаблонные литералы**: `` type Route = `/api/${string}` ``.
- **`satisfies`**: проверить, что значение подходит к типу, не расширяя его вывод.

<Callout kind="warn" title="Где TypeScript не защищает">
Типы стираются при компиляции — во время выполнения их нет. Ответ API, `JSON.parse`, `localStorage`, данные формы — это `unknown`, пока не проверены. Приведение `as User` ничего не проверяет. Для внешних данных — валидация схемой (Zod, Valibot), которая и проверяет, и выводит тип.
</Callout>

<Takeaways>
- Типизация **структурная**; для различения одинаковых форм — брендированные типы.
- Проверки в коде **сужают** тип; лучший инструмент — **дискриминированные объединения**.
- Делай некорректные состояния непредставимыми; полноту `switch` проверяй через `never`.
- Дженерики, `keyof`, условные и шаблонные типы, `satisfies`.
- Во время выполнения типов нет: внешние данные — `unknown` + валидация схемой.
</Takeaways>
