Большая часть багов во фронтенде — не в вёрстке, а в управлении состоянием: дублирующиеся данные, которые расходятся, эффекты, которые срабатывают не тогда, и гонки асинхронных запросов. Хорошая новость: большинство `useEffect` в типичном коде можно просто удалить.

## Где держать состояние

- **Минимум состояния**: всё, что можно вычислить из пропсов и другого состояния, вычисляй во время рендера, а не храни. `fullName = first + " " + last` — не состояние.
- **Поднимай состояние** к ближайшему общему родителю тех, кому оно нужно.
- **Серверные данные** — это не состояние компонента, а кэш: React Query / SWR / RTK Query решают кэширование, повторные запросы, инвалидацию и гонки.
- **URL** — тоже состояние: фильтры, вкладки, страница. Его можно отправить ссылкой.
- **Глобальный стор** (Zustand, Redux) — для действительно глобальных вещей; контекст — для редко меняющихся (тема, пользователь), иначе он перерисует всех потребителей.

## Когда useEffect не нужен

`useEffect` — для синхронизации с **внешними** системами: подписки, таймеры, сетевые запросы, сторонние виджеты, DOM вне React. Он не нужен, чтобы:

- **вычислить** что-то из состояния → вычисли в рендере (`useMemo`, если дорого);
- **отреагировать на действие пользователя** → делай это в обработчике события;
- **сбросить состояние при смене пропса** → передай `key`;
- **«синхронизировать» одно состояние с другим** → это признак лишнего состояния.

Каждый лишний эффект — лишний рендер и шанс на рассинхронизацию.

## Гонки в эффектах

Классика — поиск при вводе: каждый символ запускает запрос, а ответы приходят в произвольном порядке:

```tsx
useEffect(() => {
  const ctrl = new AbortController();
  fetch(`/api/search?q=${q}`, { signal: ctrl.signal })
    .then((r) => r.json())
    .then(setResults)
    .catch((e) => { if (e.name !== "AbortError") setError(e); });
  return () => ctrl.abort();          // cleanup: отменить устаревший запрос
}, [q]);
```

Cleanup-функция эффекта вызывается перед следующим запуском и при размонтировании. Именно поэтому в Strict Mode React в разработке монтирует компоненты дважды — чтобы забытый cleanup проявился сразу.

<Callout kind="tip" title="Замыкания и устаревшие значения">
Колбэк в `setInterval` внутри эффекта с пустыми зависимостями навсегда видит `count` из первого рендера. Решения: функциональная форма `setCount(c => c + 1)`, правильный массив зависимостей (линтер `react-hooks/exhaustive-deps`), `useRef` для изменяемого значения, не вызывающего рендер.
</Callout>

<Takeaways>
- Минимум состояния: **производное вычисляй в рендере**.
- Серверные данные — в кэш-библиотеке (React Query/SWR); URL — тоже состояние.
- `useEffect` — только для синхронизации с **внешним миром**; реакции на действия — в обработчиках.
- Асинхронные эффекты — с **cleanup** (AbortController / флаг), иначе гонки и обновления размонтированных компонентов.
- Замыкания видят значения своего рендера: функциональные обновления, зависимости, `useRef`.
</Takeaways>
