Тони Хоар, придумавший `null` в 1965 году для языка ALGOL W, назвал это своей **ошибкой на миллиард долларов**. Обработка ошибок — та часть кода, которую пишут в последнюю очередь и читают в самый неподходящий момент: во время инцидента. Здесь чистота кода особенно окупается.

## Исключения против кодов ошибок

В Java исключения — основной механизм. Но есть и альтернатива, о которой стоит знать: **ошибка как значение** (`Result<T, E>` в Rust, `Either` в функциональных языках, `sealed`-иерархии в современной Java). Её выбирают, когда ошибка — **ожидаемый бизнес-исход**, а не сбой: «платёж отклонён» — это не авария, а нормальный вариант ответа. Подробнее — в треке ФП.

## Правила хорошей обработки

**1. Fail fast.** Проверяй входные данные на границе и падай сразу, с понятным сообщением. Чем дальше ошибка уходит от места появления, тем дороже её искать.

```java
public Transfer(AccountId from, AccountId to, Money amount) {
    this.from = Objects.requireNonNull(from, "from");
    this.to = Objects.requireNonNull(to, "to");
    if (!amount.isPositive()) throw new IllegalArgumentException("amount must be > 0: " + amount);
    if (from.equals(to)) throw new IllegalArgumentException("transfer to self");
    this.amount = amount;
}
```

**2. Не глотай исключения.** Пустой `catch` — худший код в проекте: ошибка случилась, следов нет.

```java
try { sync(); } catch (Exception e) { }                 // ← никогда
try { sync(); } catch (Exception e) { e.printStackTrace(); }   // ← почти так же плохо в проде
```

Либо обработай по-настоящему (повтори, верни значение по умолчанию **осознанно**, покажи пользователю), либо пробрось дальше.

**3. Сохраняй причину.** Оборачивая исключение, передавай исходное как cause — иначе стек-трейс оборвётся на твоём уровне.

```java
catch (SQLException e) {
    throw new RepositoryException("не удалось сохранить заказ " + order.id(), e);   // e — cause
}
```

**4. Сообщение — для того, кто будет чинить.** Не `"error"`, а что случилось и с какими данными: `"заказ 812 не найден для клиента 55"`. Но без паролей, токенов и номеров карт.

**5. Ловить на нужном уровне.** Репозиторий не знает, что делать с ошибкой сети, — пусть пробросит. Контроллер знает: вернуть 503 и залогировать. Единый обработчик (`@ControllerAdvice` в Spring) превращает типы исключений в HTTP-ответы в одном месте.

## null: что делать с ошибкой на миллиард

`NullPointerException` — самая частая ошибка в Java. Защиты, от сильной к слабой:

1. **Не возвращай null.** Пустая коллекция вместо `null`-списка, `Optional` вместо «может быть null».
2. **`Optional` для возвращаемого значения**, которого может не быть:
   ```java
   Optional<User> findByEmail(String email);
   String name = users.findByEmail(e).map(User::name).orElse("гость");
   ```
   `Optional` не для полей и параметров — там он только мешает.
3. **Проверка на входе** — `Objects.requireNonNull` в конструкторах.
4. **Аннотации** `@Nullable`/`@NonNull` (JSpecify) + анализатор (NullAway) — компилятор ловит нарушения.
5. **Неизменяемые объекты**, у которых все поля заданы в конструкторе: полу-созданных объектов с `null` не бывает.

<Callout kind="info" title="Как это решили другие языки">
В Kotlin, Swift, TypeScript (strict) и Rust тип по умолчанию **не может быть null**: `String` и `String?` — разные типы, и компилятор заставляет обработать случай «нет значения». Это и есть исправление ошибки Хоара.
</Callout>

## Checked или unchecked

| | checked (`IOException`) | unchecked (`RuntimeException`) |
|---|---|---|
| компилятор заставляет обработать | да | нет |
| для чего задумывались | ожидаемые сбои, которые вызывающий может исправить | ошибки программиста: null, неверный аргумент |
| на практике | неудобны в лямбдах; их заворачивают | почти весь современный код (Spring, JPA) |

Разумная позиция: свои исключения делай **unchecked**, называй по смыслу (`OrderNotFoundException`), а checked из библиотек оборачивай на границе.

<Takeaways>
- Исключения нельзя случайно проигнорировать, в отличие от кодов ошибок. Ожидаемые бизнес-исходы можно моделировать как **значения** (`Result`, sealed-типы).
- **Fail fast** на границе; **не глотай** исключения; **сохраняй причину** (cause); пиши сообщения для того, кто будет чинить.
- Ловить там, где есть что сделать; единый обработчик на краю (контроллер).
- `null` — ошибка на миллиард: не возвращай его, `Optional` для результатов, проверки на входе, аннотации и неизменяемость.
- Свои исключения — unchecked с говорящими именами.
</Takeaways>
