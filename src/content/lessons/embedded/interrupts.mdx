Прерывание — способ железа сказать процессору «срочно, бросай всё»: пришёл байт, сработал таймер, нажата кнопка. Процессор приостанавливает текущий код, выполняет **обработчик** (ISR) и возвращается. Это даёт реакцию за микросекунды без постоянного опроса — и создаёт все классические проблемы конкурентности даже на одном ядре.

## Как это работает на Cortex-M

1. Периферия выставляет запрос; контроллер прерываний **NVIC** проверяет, разрешено ли оно и выше ли его приоритет текущего.
2. Процессор аппаратно сохраняет на стек часть регистров (r0–r3, r12, lr, pc, xPSR) и прыгает по адресу из **таблицы векторов**.
3. ISR выполняется. Она должна сбросить флаг в периферии — иначе прерывание тут же сработает снова.
4. Возврат — регистры восстанавливаются, основной код продолжается, не заметив паузы.

Прерывания имеют **приоритеты**: более важное может прервать менее важное (вложенность). Задержка входа на Cortex-M — ~12 тактов, то есть доли микросекунды.

## Правила хорошей ISR

- **Коротко**: выставить флаг, положить байт в кольцевой буфер, разбудить задачу — и выйти. Обработка — в основном цикле или задаче RTOS.
- **Никаких блокировок и ожиданий**: нельзя ждать мьютекс, `printf` с блокирующим UART, `malloc`.
- Общие переменные с основным кодом — **volatile** и **атомарный доступ**.
- Не забывать **сбросить флаг** источника.

## Гонка без потоков

Даже на одноядерном 8-битном микроконтроллере ISR может сработать между любыми двумя инструкциями основного кода. 16-битная переменная читается двумя инструкциями — и может быть прочитана «наполовину до, наполовину после»:

Решения:

- **критическая секция**: запретить прерывания на время доступа (`__disable_irq()` / `cli`) — коротко, иначе вырастет задержка реакции;
- **атомарные типы** нужной разрядности или инструкции `LDREX/STREX` на Cortex-M;
- **читать дважды**, пока значения не совпадут;
- **кольцевой буфер с одним писателем и одним читателем**: ISR двигает только head, основной код — только tail; при правильных барьерах блокировки не нужны.

<Callout kind="info" title="Опрос, прерывания, DMA">
**Опрос** (polling) — проще всего, но процессор занят ожиданием. **Прерывания** — реакция без ожидания, но на каждый байт — вход в ISR. **DMA** — контроллер сам перекладывает данные между периферией и памятью, а прерывание приходит только когда весь буфер готов. На высоких скоростях (аудио, быстрый SPI, АЦП) — только DMA.
</Callout>

<Takeaways>
- Прерывание: NVIC → аппаратное сохранение контекста → ISR из таблицы векторов → возврат.
- ISR — **короткая**, без блокировок; сбросить флаг; работу — в основной цикл/задачу.
- Общие данные — `volatile` + **атомарность**: критические секции, атомики, двойное чтение.
- Кольцевой буфер «один писатель — один читатель» — стандартная связь ISR и основного кода.
- Polling → прерывания → DMA по мере роста скорости данных.
</Takeaways>
