На микроконтроллере нет драйверов и ОС между тобой и железом. Периферия — UART, таймеры, GPIO — управляется **регистрами**, которые выглядят как обычные адреса памяти. Писать в них — значит включать светодиоды и отправлять байты. И именно здесь компилятор, привыкший оптимизировать «обычную» память, ломает программы.

## Memory-mapped I/O

Регистры периферии отображены в адресное пространство процессора. В даташите на STM32: «USART2 начинается с 0x40004400, регистр статуса SR — смещение 0x00, данные DR — 0x04». В коде:

```c
typedef struct {
    volatile uint32_t SR;   // статус: биты RXNE (байт принят), TXE (можно передавать)
    volatile uint32_t DR;   // данные
    volatile uint32_t BRR;  // делитель скорости
    volatile uint32_t CR1;  // управление
} USART_TypeDef;

#define USART2 ((USART_TypeDef *) 0x40004400)

while (!(USART2->SR & USART_SR_TXE)) {}   // ждём, пока передатчик свободен
USART2->DR = 'A';                          // запись в регистр = отправка байта
```

Чтение регистра может иметь **побочный эффект** (чтение DR сбрасывает флаг RXNE), а значение может измениться **без участия программы** (железо выставило флаг).

## volatile

Для компилятора обычная переменная, которую никто в цикле не меняет, — константа. Он вправе прочитать её один раз и крутить цикл вечно:

`volatile` говорит: каждое обращение в исходнике — реальное обращение к памяти, в том же количестве и порядке относительно других volatile-обращений. Нужен для:

- регистров периферии;
- переменных, которые меняет обработчик прерывания, а читает основной цикл;
- памяти, которую пишет DMA.

`volatile` **не** даёт атомарности и **не** является барьером для обычных переменных и для других ядер — для этого нужны атомики, барьеры (`__DMB()`) или запрет прерываний (следующий урок).

## Read-modify-write и битовые операции

```c
GPIOA->ODR |= (1 << 5);    // включить пин 5: прочитать, OR, записать
GPIOA->ODR &= ~(1 << 5);   // выключить
GPIOA->BSRR = (1 << 5);    // атомарная установка через регистр set/reset
```

Read-modify-write из трёх инструкций можно прервать прерыванием, которое меняет тот же регистр, — его изменение потеряется. Поэтому у многих периферийных блоков есть отдельные регистры «установить биты» / «сбросить биты» (BSRR), а у Cortex-M — bit-banding.

<Callout kind="tip" title="HAL или регистры">
Библиотеки производителя (STM32 HAL, ESP-IDF) скрывают регистры за функциями — быстрее начать, но больше кода и накладных расходов. На собесе ждут, что ты понимаешь, что под ними: запись битов в регистры по даташиту и reference manual.
</Callout>

<Takeaways>
- Периферия управляется **регистрами по фиксированным адресам** (MMIO); адреса и биты — из reference manual.
- Чтение и запись регистров имеют **побочные эффекты**, значение меняет железо.
- **volatile** — каждое обращение реально выполняется; нужен для регистров, переменных ISR и DMA-буферов.
- volatile ≠ атомарность и ≠ барьер между ядрами.
- Read-modify-write прерываем → регистры set/reset, критические секции.
</Takeaways>
