STL-контейнеры — это те же структуры данных из алгоритмического трека, но с конкретными гарантиями сложности и, главное, **правилами инвалидации**: какие операции делают недействительными итераторы, указатели и ссылки на элементы. Нарушение этих правил — UB, который проявляется через раз.

## Что внутри

| Контейнер | Внутри | Доступ | Вставка |
|---|---|---|---|
| `vector` | динамический массив | O(1) по индексу | O(1) амортизированно в конец, O(n) в середину |
| `deque` | массив блоков фиксированного размера | O(1) | O(1) в оба конца |
| `list` | двусвязный список | O(n) | O(1) при известной позиции |
| `map` / `set` | красно-чёрное дерево | O(log n), упорядочено | O(log n) |
| `unordered_map` / `set` | хеш-таблица на цепочках | O(1) в среднем | O(1) в среднем, rehash O(n) |
| `priority_queue` | двоичная куча на `vector` | top O(1) | O(log n) |

По умолчанию — `vector`: он быстрее всех на практике из-за кэша (см. урок про массивы и списки). `unordered_map` в стандартной библиотеке медленнее, чем мог бы быть: требования стандарта (стабильность ссылок на элементы, интерфейс бакетов) вынуждают делать цепочки с отдельной аллокацией на каждый узел. Поэтому в производительном коде используют `absl::flat_hash_map` или `boost::unordered_flat_map` с открытой адресацией.

## Инвалидация

Основные правила:

- **`vector`**: вставка, вызвавшая рост, инвалидирует **всё**; вставка без роста — всё после места вставки; `erase` — всё начиная с удалённого. Если заранее знаешь размер — `reserve`.
- **`deque`**: вставка в концы инвалидирует итераторы, но **не** ссылки на элементы; в середину — всё.
- **`list`, `map`, `set`**: узлы не двигаются — инвалидируется только итератор на удалённый элемент.
- **`unordered_map`**: rehash инвалидирует итераторы, но ссылки и указатели на элементы остаются валидными (узлы не двигаются).

Классический баг — удаление в цикле:

```cpp
for (auto it = v.begin(); it != v.end(); ) {
    if (bad(*it)) it = v.erase(it);   // erase возвращает следующий валидный итератор
    else ++it;
}
// а проще и быстрее — erase-remove (C++20: std::erase_if(v, bad))
```

## Мелочи, о которых спрашивают

- `map[key]` **вставляет** элемент по умолчанию, если ключа нет. Для проверки — `find` или `contains` (C++20).
- `vector<bool>` — не настоящий контейнер `bool`, а упакованные биты; ссылка на элемент — прокси-объект.
- `std::sort` требует итераторы произвольного доступа — у `list` свой `list::sort`.
- `emplace_back` строит на месте, `push_back` копирует или перемещает готовый объект.
- `string_view` и `span` — невладеющие «окна» в чужие данные; переживут источник — висячая ссылка.

<Takeaways>
- `vector` — по умолчанию; `map` — дерево, упорядочено, O(log n); `unordered_map` — хеш, O(1) в среднем.
- Знай правила **инвалидации**: рост `vector` инвалидирует всё; узловые контейнеры — только удалённый элемент.
- Удаление в цикле — через возвращаемый `erase` итератор или `std::erase_if`.
- `map[k]` вставляет; `string_view`/`span` не владеют данными.
- Для скорости хеш-таблиц — flat-реализации с открытой адресацией.
</Takeaways>
