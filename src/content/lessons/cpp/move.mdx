До C++11 вернуть из функции большой `vector` или положить `string` в контейнер означало скопировать все данные. **Move-семантика** позволяет вместо копирования «украсть» ресурсы у объекта, который всё равно сейчас умрёт. Это одна из причин, по которой современный C++ быстрый без ручной оптимизации.

## lvalue и rvalue

- **lvalue** — у выражения есть имя и адрес, оно переживёт текущее выражение: переменная `a`, `v[0]`, `*p`.
- **rvalue** — временное значение, которое сейчас исчезнет: `a + b`, `std::string("x")`, результат функции, возвращающей по значению.

Из rvalue можно забрать внутренности — им они больше не понадобятся. Для этого есть **rvalue-ссылки** `T&&` и перемещающие конструктор и присваивание:

```cpp
class Buffer {
    char* data_; size_t size_;
public:
    Buffer(const Buffer& o) : data_(new char[o.size_]), size_(o.size_) {   // копия: O(n)
        std::memcpy(data_, o.data_, size_);
    }
    Buffer(Buffer&& o) noexcept : data_(o.data_), size_(o.size_) {         // перемещение: O(1)
        o.data_ = nullptr; o.size_ = 0;   // источник — в валидное пустое состояние
    }
};
```

## std::move ничего не перемещает

`std::move(x)` — просто приведение `x` к `T&&`: «можешь украсть». Перемещение выполняет конструктор, который будет выбран благодаря этому типу. После перемещения объект **валиден, но не определён** — его можно уничтожить или присвоить новое значение, но не стоит полагаться на содержимое.

## Где перемещение происходит само

- **Возврат по значению**: `return local;` — сначала пытается RVO/NRVO (объект строится сразу на месте результата, без копий и перемещений), иначе перемещает. Поэтому `return std::move(local);` — **вредно**: ломает NRVO.
- Временные объекты: `v.push_back(std::string("x"))` перемещает.
- `emplace_back(args...)` строит объект прямо в контейнере — даже без перемещения.

## noexcept важен

Когда `std::vector` растёт, он переносит элементы в новый буфер. Если перемещающий конструктор элемента **не** `noexcept`, вектор **копирует** их — иначе при исключении посреди переноса нельзя было бы откатиться к старому состоянию (строгая гарантия). Помечай перемещающие операции `noexcept` — для `vector<YourType>` это разница O(n) копий на каждом росте.

<Callout kind="tip" title="Передача параметров">
Принимаешь, чтобы только читать — `const T&`. Принимаешь, чтобы сохранить у себя (в поле, контейнер) — принимай **по значению** и делай `std::move` внутрь: вызывающий сам решит, копировать или передать временный объект. Мелкие типы (int, указатели, `string_view`) — по значению.
</Callout>

<Takeaways>
- **rvalue** — временное, его ресурсы можно забрать; **`T&&`** и перемещающие операции делают это за O(1).
- `std::move` — только приведение типа; перемещает конструктор.
- Moved-from объект — валиден, но не определён.
- Возврат по значению: RVO/NRVO, не пиши `return std::move(x)`.
- Перемещение помечай **`noexcept`** — иначе `vector` при росте копирует.
</Takeaways>
