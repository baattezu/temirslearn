Главная идея C++ — не классы и не шаблоны, а **RAII** (Resource Acquisition Is Initialization): ресурс принадлежит объекту, захватывается в конструкторе и освобождается в деструкторе. Деструктор вызывается автоматически, когда объект выходит из области видимости, — в том числе при исключении. Поэтому в хорошем C++ почти нет ручного `delete`, `close` и `unlock`.

## Проблема

Ресурсов много: память, файлы, сокеты, мьютексы, транзакции. В C каждый путь выхода из функции должен всё освободить, и любой забытый `return` или ошибка — утечка. В C++ к этому добавляются исключения: выйти из функции можно с **любой** строки.

## Как это гарантируется

- Деструкторы локальных объектов вызываются при выходе из области видимости — нормальном, по `return`, `break` или исключению (**раскрутка стека**).
- Порядок — **обратный** порядку создания: последний созданный уничтожается первым. Поэтому объект может спокойно опираться на тех, кто создан раньше.
- Члены класса уничтожаются после тела деструктора, в обратном порядке объявления.

## Стандартные RAII-обёртки

| Ресурс | Обёртка |
|---|---|
| память, единственный владелец | `std::unique_ptr<T>` |
| память, совместное владение | `std::shared_ptr<T>` (счётчик ссылок) |
| мьютекс | `std::lock_guard`, `std::scoped_lock`, `std::unique_lock` |
| файл | `std::fstream` |
| поток | `std::jthread` (join в деструкторе) |
| своё | класс с конструктором и деструктором, или `unique_ptr` с собственным deleter |

`unique_ptr` ничего не стоит по сравнению с сырым указателем (тот же размер, нет счётчика), поэтому он — выбор по умолчанию. `shared_ptr` — только когда владение действительно общее: у него атомарный счётчик ссылок (дорого) и риск циклов (лечится `weak_ptr`).

## Правило нуля, трёх, пяти

- **Правило нуля**: если класс владеет ресурсами только через RAII-члены (`vector`, `unique_ptr`, `string`), не пиши деструктор, копирование и перемещение вообще — сгенерированные будут правильными.
- **Правило трёх/пяти**: если всё-таки пишешь деструктор (класс сам управляет сырым ресурсом), то нужны и копирующие конструктор и присваивание, и перемещающие — иначе сгенерированное копирование скопирует указатель, и два объекта освободят его дважды.

<Callout kind="warn" title="Деструкторы не должны бросать">
Если деструктор бросит исключение во время раскрутки стека от другого исключения, вызывается `std::terminate`. С C++11 деструкторы неявно `noexcept`. Ошибки при очистке (например, неудачный `close`) логируют, а не бросают.
</Callout>

<Takeaways>
- **RAII**: ресурс захватывается в конструкторе, освобождается в деструкторе.
- Деструкторы вызываются **при любом выходе** из области, включая исключения, в **обратном** порядке создания.
- По умолчанию `unique_ptr`; `shared_ptr` — только для общего владения (`weak_ptr` от циклов).
- **Правило нуля**: владей через RAII-члены и не пиши специальные функции.
- Деструкторы не бросают исключений.
</Takeaways>
