Функция высшего порядка — функция, которая **принимает или возвращает другую функцию**. Звучит экзотично, а пользуешься постоянно: `list.sort(comparator)`, `executor.submit(task)`, `button.onClick(handler)`. Функциональный стиль просто доводит идею до конца: почти любую обработку данных можно собрать из трёх кирпичей — **map, filter, reduce**.

## Три кирпича

- **map** — преобразовать каждый элемент: `x → x * x`, `order → order.total()`.
- **filter** — оставить подходящие: `x → x % 2 == 0`.
- **reduce** — свернуть всё в одно значение: сумма, максимум, склейка строк.

## Лямбды и ссылки на методы

В Java функция передаётся как объект **функционального интерфейса** — интерфейса с одним абстрактным методом. Лямбда — короткая запись его реализации:

```java
Predicate<Order> isPaid = o -> o.status() == PAID;          // T → boolean
Function<Order, BigDecimal> total = Order::total;            // T → R, ссылка на метод
BinaryOperator<BigDecimal> sum = BigDecimal::add;            // (T, T) → T
Supplier<UUID> ids = UUID::randomUUID;                       // () → T
Consumer<String> print = System.out::println;                // T → void

// функции можно комбинировать
Predicate<Order> bigPaid = isPaid.and(o -> o.total().compareTo(LIMIT) > 0);
Comparator<User> byCityThenAge = Comparator.comparing(User::city).thenComparing(User::age);
```

Лямбда может захватывать переменные снаружи, но только **effectively final** — те, что не меняются. Это защита от гонок: лямбду могут выполнить в другом потоке.

## Стримы ленивые

Главное, что стоит понимать про Stream API: промежуточные операции (`filter`, `map`, `sorted`) **ничего не делают**, пока не вызвана терминальная (`toList`, `sum`, `findFirst`, `count`). А когда вызвана — элементы проходят **весь конвейер по одному**, а не этапами. Посмотри на разницу:

Отсюда два следствия:

- **короткое замыкание**: `limit`, `findFirst`, `anyMatch` останавливают обработку, как только ответ известен. Можно даже работать с бесконечными стримами: `Stream.iterate(1, x -> x * 2).limit(10)`;
- **нет промежуточных коллекций**: фильтр и map не создают списков между шагами.

Исключение — операции, которым нужно видеть всё: `sorted()` и `distinct()` сначала собирают элементы.

## Ловушки стримов

```java
// 1. Побочные эффекты в стриме — плохо
List<String> out = new ArrayList<>();
users.stream().map(User::name).forEach(out::add);     // работает, но мимо идеи
List<String> out2 = users.stream().map(User::name).toList();   // так

// 2. Стрим одноразовый
Stream<User> s = users.stream();
s.count();
s.count();   // IllegalStateException: stream has already been operated upon

// 3. parallel() — не бесплатное ускорение
list.parallelStream().map(this::callHttp)...   // общий ForkJoinPool, блокирующие вызовы — плохо
```

`parallelStream` помогает только на больших CPU-задачах без блокировок и общего состояния. Для сетевых вызовов — виртуальные потоки или асинхронный клиент.

## Когда цикл лучше

Стрим не обязателен везде. Цикл понятнее, если:

- нужна сложная логика с несколькими состояниями и ранним выходом из вложенных уровней;
- нужно бросать checked-исключения изнутри;
- горячий код над примитивными массивами, где важна каждая наносекунда.

Критерий тот же, что везде: что легче прочитать.

<Takeaways>
- Функция высшего порядка принимает или возвращает функцию. В Java функция — это **функциональный интерфейс**, лямбда — его короткая реализация.
- Почти любая обработка данных — это **map, filter, reduce**: описываешь «что», а не «как».
- Стримы **ленивые**: ничего не происходит до терминальной операции, элементы проходят конвейер **по одному**, `limit`/`findFirst` замыкают накоротко.
- Ловушки: побочные эффекты внутри, повторное использование стрима, бездумный `parallel()`.
- Цикл лучше, когда логика сложная или код горячий: критерий — читаемость.
</Takeaways>
