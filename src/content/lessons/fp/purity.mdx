Функция **чистая**, если: (1) её результат зависит только от аргументов и (2) у неё нет побочных эффектов — она ничего не меняет снаружи: ни полей, ни файлов, ни базы, ни глобальных переменных. Звучит академично, но на практике это самое полезное свойство кода, которое можно получить бесплатно.

## Ссылочная прозрачность

Если функция чистая, её вызов можно **заменить её результатом**, и программа не изменится. `square(4)` можно везде заменить на `16`. Это называют **ссылочной прозрачностью**, и из неё вытекает всё хорошее:

- **тестировать** — дать вход, проверить выход, без моков и настройки окружения;
- **кэшировать** (мемоизация) — повторный вызов с теми же аргументами можно не считать;
- **распараллеливать** — вызовы не мешают друг другу;
- **рассуждать** — чтобы понять функцию, достаточно прочитать её саму.

## Функциональное ядро, императивная оболочка

Программа без эффектов бесполезна: надо читать запросы, писать в базу, отправлять письма. Поэтому цель не «убрать все эффекты», а **вынести их на край**. Гэри Бернхардт назвал это **«функциональное ядро, императивная оболочка»**:

- **ядро** — чистая бизнес-логика: расчёты, правила, решения. Его легко тестировать и менять;
- **оболочка** — тонкий слой, который достаёт данные, вызывает ядро и выполняет решения ядра.

Та же идея в архитектуре — «гексагональная» или «чистая» архитектура: домен в центре ничего не знает о базе и HTTP.

## Неизменяемость

Вторая половина ФП — **не менять данные, а создавать новые**.

```java
record Money(BigDecimal amount, String currency) {
    Money plus(Money other) {
        if (!currency.equals(other.currency)) throw new IllegalArgumentException("разные валюты");
        return new Money(amount.add(other.amount), currency);   // новый объект, старый не тронут
    }
}

List<String> names = List.of("Ада", "Алан");           // неизменяемый список
List<String> more = Stream.concat(names.stream(), Stream.of("Грейс")).toList();
```

Почему это стоит лишних аллокаций:

- **нет гонок**: неизменяемое можно отдавать в любые потоки;
- **нет «действия на расстоянии»**: ты передал объект в метод — он не изменится у тебя за спиной;
- **безопасные ключи**: неизменяемый объект можно класть в `HashMap` — его хеш не поменяется;
- **история бесплатно**: старая версия никуда не делась — undo, аудит, сравнение.

Сборщики мусора в JVM оптимизированы именно под короткоживущие объекты, поэтому новые маленькие `record` почти бесплатны.

<Callout kind="warn" title="Ловушка: «неизменяемый» снаружи, изменяемый внутри">
`record Order(List<Line> lines)` — сам record неизменяем, но список внутри — нет: `order.lines().add(x)` пройдёт. Защищайся копией в конструкторе: `Order { lines = List.copyOf(lines); }`.
</Callout>

## Где нужна осторожность

Чистота — не догма. Горячие циклы над большими массивами в Java честнее писать с изменяемым массивом — копирование на каждом шаге убьёт производительность. Правило: **внутри функции можно мутировать локальные данные**, если наружу эффект не виден. Функция остаётся чистой для вызывающего.

<Takeaways>
- **Чистая функция**: результат только от аргументов, без побочных эффектов. Её вызов можно заменить результатом (**ссылочная прозрачность**).
- Плюсы: легко тестировать, кэшировать, распараллеливать, понимать.
- **Функциональное ядро, императивная оболочка**: правила — чистые, эффекты (БД, сеть, лог) — на краю.
- **Неизменяемость**: новые объекты вместо изменений — нет гонок и действий на расстоянии. Следи за изменяемыми коллекциями внутри record.
- Локальная мутация внутри функции допустима, если снаружи она не видна.
</Takeaways>
